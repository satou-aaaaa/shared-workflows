# カンバンのアプリ版が、10/25 から古いカードを読み続けていた

- 種類: 手順の抜け
- 場所: カンバンのアプリ版（local-kanban）とデータ側の控えリポジトリ、毎時の取り込み・見回りの定期実行
- 気づいた人: 「カンバンをアプリ版に一本化」スレッド（一本化の下調べで）
- 影響: 10/25〜10/29 のあいだ、アプリ版は 149 枚の古いカードを表示していた（ボードは 210 枚）。アプリで答えたもののうち2件が、届いていない印のまま残った。毎時の取り込みは、写しがあるので毎回全部の手順を回し、トークンを多く使っていた。

## 起きたこと
- アプリは、データ側の `local-board/cards.json`（アプリで直したもの）があればそれを、無ければ毎日の写し `board/cards.json` を読む。
- 取り込みの手順は「取り込んだら `local-board/cards.json` を git rm する」だった。10/25 に控えのリポジトリの履歴を作り直したとき、この写しが残った。
- その後、毎時の取り込みと見回りは写しがあるので取り込みを回したが、新しい会話では削除が安全の仕組みに止められ、写しは消えなかった。止められたことはどこにも出なかった。

## 原因
- 正が2つ（ボードとアプリの写し）あり、「写しを消すとボードの写しに戻る」という消すことに頼る仕組みだった。消せないと、だまって古い方を読み続けた。
- アプリにも検査にも、「アプリが読む写しが、ボードの写しより古い」を見るものが無かった。

## なぜ見つからなかったか
- 取り込みの定期実行は、うまくいかなかった回も「変わりなし」と同じ終わり方をした。
- アプリの検査（qa/run.mjs）は見本のデータで回り、本物の写しの新しさを見ていなかった。

## 対策
- [x] 直す: アプリ版の写しを最新のボードの写し（210 枚）で作り直し、それを正にした（カンバンをアプリ版に一本化。控えのリポジトリの PR #84）
- [x] 防ぐ: 消すことに頼る受け渡しをやめた。正は1つ（アプリ版）で、ボードの写しは `local_board.py merge-board` で正に重ねる（新しいほうを採り、履歴は合わせる。届いていないものは消さない）。毎時の取り込みは無効にした
- [x] 見つける: `local_board.py check` が、ボードの写しのほうが新しいカードがあると毎回知らせる（テスト `tools/test_local_board.py`）
