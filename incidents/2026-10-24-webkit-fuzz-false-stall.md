# last-tell の main の QA が、進んでいた WebKit の自動対戦（第5章）を「止まった」として ❌ にした

- 種類: 公開・CI
- 場所: satou-aaaaa/last-tell の QA（qa/checks/fuzz.js・qa/lib/harness.js）
- 気づいた人: CI（main の QA が Issue を立てた）
- 影響: main（v0.98.12）の QA が ❌、Issue が2件（last-tell #152・#153）。ゲームの不具合ではなく、遊ぶ人への影響は無い。同じ版の PR #150 の CI では ✅。

## 起きたこと
- 10/24 19:03 UTC、main の QA で「WebKit：自動対戦 第5章：止まった（1ハンド目の preflop）」。
- 記録では、止まったと判定した 0.5秒前にも「進める処理」が動き、相手（席5）の動きも 0.6秒前に済んでいた。50ms のタイマーが 773ms かかっていた。
- 同じ第5章・WebKit の止まりは v0.98.9 でも出て、そのときは記録の項目を足しただけだった。

## 原因
- 「止まった」の判定が「ハンドが20秒終わらない」だけだった。CI の WebKit が混んで遅いと、会話と演出の多い第5章の1ハンド目が20秒を超え、進んでいても ❌ になった。
- 「ページが詰まっている」の見分け（ボットのタイマーが20秒で200回）は、1秒に10回動けば詰まっていないとみなすので、遅いだけの WebKit を通さなかった。

## なぜ見つからなかったか
- 止まったときの記録が誤って見えていた：操作パネルを offsetParent で見ていたので、PC 幅の固定パネルではいつも「ボタンなし」と出た。WebKit は長い処理（longtask）を測れないのに「0回」と出て、ページが詰まっていないように見えた。v0.98.9 のときも「ゲームの止まり」に見え、判定そのものは見直さなかった。
- 判定は fuzz と runUntilDone の2か所に別々に書かれ、どちらにもテストが無かった。

## 対策
- [x] 直す: 「止まった」を、ハンドが20秒終わらず、かつゲームの進む印（ハンド・通り・番・進める処理の回数・ボットの押した数）も20秒変わらないときにした。印が変わり続けても2分終わらなければ止まり（本当の止まりは今までどおり20秒で ❌。last-tell #154）
- [x] 防ぐ: 判定を `qa/lib/stall.js` の1つにまとめ、fuzz と runUntilDone（rules・basics・winrate・save など）が同じものを使う。10/24 の場面を入れた単体テスト `qa/unit/tests/stall.js` を `node qa/unit/run.js` が見る（last-tell #154）
- [x] 見つける: 止まったときの記録に「ハンドが終わってから○秒・最後に進んでから○秒・タイマーの遅れ」を出し、WebKit の longtask は「測れない」、操作パネルはボットと同じ見え方で出す。次に出たら、ゲームの止まりか遅いだけかが記録だけで分かる（last-tell #154）
