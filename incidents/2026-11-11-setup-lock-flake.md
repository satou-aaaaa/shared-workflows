# main の Lint が1回だけ赤：setup.sh を2つ同時に動かす検査で npm ci が重なった

- 種類: 公開・CI
- 場所: satou-aaaaa/shared-workflows の `scripts/check-setup-template.sh`「17. 2つ同時に動いても両方通る」（`template/scripts/setup.sh` のロック）
- 気づいた人: 見回り（#282 のマージ直後の main の Lint、run 43005154766）
- 影響: main の Lint が約40分赤。同じ run をもう一度回すと緑。各ゲームの setup.sh で困った報告は無い。

## 起きたこと
- 2つ同時に動かした setup.sh の片方が `npm ci` で `EEXIST: symlink '../pw' -> app/node_modules/playwright` で止まった。もう片方は通った。
- 片方の npm が動き始めたのは検査の開始から約0.1秒後で、もう片方の npm ci と時間が重なっていた。ロックの「外した」行は出ていない。
- #282 は setup.sh にも検査にも触れていない。この検査は #282 の PR の CI では5回とも通っていた。

## 原因
- まだ分からない。2つの npm ci が重なったことは確かだが、ロック（`mkdir`・名札・古いロックの外し方）を読んでも重なる道が見つからない。
- 手元で、同じ形の検査を約300回（CPU 1つに絞ったものも）、全体の検査を4回同時に回しても再現しなかった。前に同じ形で落ちたのは 11/7（ロックを入れた版11の作りかけ）だけ。

## なぜ見つからなかったか
- 検査が落ちたとき、2つの出力しか残らず、どちらがいつロックを取ったか分からなかった。

## 対策
- [x] 直す: main の Lint を1回だけ再実行して緑を確かめた（コードは変えていない。setup.sh のロックの形を、原因が分からないまま変えない）
- [x] 防ぐ: 検査17は、2つの setup.sh を時刻つき（`EPOCHREALTIME`・プロセス番号）の `bash -x` で動かし、落ちたときにロックと npm ci の行を時刻順に出す。次に落ちたら、ロックをどちらがいつ取ったかがそのまま分かる（この PR）。分かったら setup.sh を直し、ここに書き足す。
