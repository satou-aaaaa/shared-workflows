# 引き継ぎコードの部品が、作ったコードで画面にスクリプトを入れられる形だった

- 種類: 検査の見逃し
- 場所: template/transfer.js（版1）と、それを写したゲーム17本の PR（まだマージ前）
- 気づいた人: CodeRabbit（seiza-tsunagi #8・rosen-hitofude #9・kasane-zome #10・bento-zume #6・mannaka-kanji #7・tenkizu-yomi #7・amida-haitatsu #4 のレビュー）
- 影響: 公開前（どのゲームの main にも入っていない）。遊ぶ人への影響は無い。

## 起きたこと
- 2026-11-05 引き継ぎコードの PR に、CodeRabbit が3種類の指摘をした。
  1. 取り込む記録の中身を確かめていなかった。ゲームは記録の値（`ebest`・`total` など）をそのまま `innerHTML` に入れるので、`<img src=x onerror=…>` を入れて作ったコード・QR を他人に開かせると、確認の画面で「入れ替える」を押したあとにスクリプトが動く。同じサイトのほかのゲームの記録も読める。
  2. `data-keys` に、全部のゲームで分け合う見やすさの設定 `a11y-v1` を入れていた。取り込むと、ほかのゲームの設定まで変わる（書き出した端末に無ければ消える）。
  3. 入れ替えてから控えを書いていた。空きが足りず控えが書けないと、前の記録が戻せないのに「引き継ぎました」と出る。

## 原因
- 部品は「コードの形・CRC・キーの名前・値が文字か」だけを見て、中身は自分の端末で作ったものと思い込んでいた。コードは人から届くもの（外から入る値）として扱っていなかった。
- `a11y-v1` は「設定も一緒に移したほうが便利」と考えて足したが、同じ origin で分け合うキーだと考えていなかった。

## なぜ見つからなかったか
- 検査（scripts/check-transfer.mjs・qa/transfer-check.mjs）が、弾くコードとして「写しまちがい・別のゲーム・知らないキー・新しい版」しか作っていなかった。危ない中身・分け合うキー・空きが無いときを試していなかった。

## 対策
- [x] 直す: template/transfer.js を版2にした。記録のキーと文字の値に `< > " ' ` + "`" + ` があるコードを弾く・`data-keys` に `a11y-v1` があると動かない・控えを先に書き、書けなければ入れ替えない。17本の PR を版2に差し替え、`data-keys` から `a11y-v1` を外した。
- [x] 防ぐ: `routines/game-dev.md`「引き継ぎコード」に「コードは他人から届く。記録の値を画面に出すときは `Number()`・`esc()` を通す」「`a11y-v1` を入れない」を足した。
- [x] 見つける: scripts/check-transfer.mjs に「HTML の印の文字が入った記録のコードを弾く（値・キーの名前）」「`a11y-v1` を data-keys に入れると動かない」「控えを書けないときは入れ替えない」を足した。各ゲームの qa（template/qa/transfer-check.mjs）にも「HTML の印の文字のコードを弾く」を足した。

## 追記（同じ日・条文討伐 jobun-tobatsu #1 のレビュー）
- CodeRabbit が4つ目を指摘した：コードを広げきってから大きさを見ていたので、0 を大量に縮めた小さなコード（50KB → 50MB など）の `#hk=` URL を開くだけでタブが固まる。
- 原因：大きさの検査を「広げたあと」に置いていた。外から届くコードは、広げる途中でも大きさを数えるものと考えていなかった。
- [x] 直す: template/transfer.js を版3にした。広げながらバイト数を数え、MAX_JSON（4MB）を超えたらそこでやめて「大きすぎ」を出す。
- [x] 見つける: scripts/check-transfer.mjs に「大きく膨らむコードを広げきる前に弾く（広げた量が 8MB 未満）」を足した（版2では 50MB 広げて落ちるのを確かめた）。各ゲームの qa（transfer-check.mjs）にも「大きく膨らむコードを弾く」を足した。
- [x] 防ぐ: `routines/game-dev.md`「引き継ぎコード」に「外から届くコードは、広げる途中でも大きさを数える」を足した。

## 追記2（同じ日・都道府県リレー #6・部首たし算 #6 のレビュー）
- CodeRabbit が小さな抜けを続けて指摘した：4MB を超える記録でもコードを作れてしまう（受け取る側で必ず弾かれる）・URL の途中の改行でコードの後半が落ちる・読み取り中に閉じると確認の箱が開き直す／古い結果で上書きする・ファイルを読めないとき・「戻す」が保存できないときに何も出ない・コピーの予備の方法が失敗しても「コピーしました」と出る・QA の 44px を丸めてから比べていた。
- 原因：うまくいく道だけを作り、失敗したとき・遅れて結果が返るときの表示を決めていなかった。
- [x] 直す: 版3のまま（まだ配っていない）ひな形に入れた。書き出しで 4MB を超えたら止める・改行をまたいでコードを取る・読み取りに番号を付けて最後の1つ（閉じたら無し）だけ画面に出す・失敗は全部「hk-err」に出す・コピーは戻り値を見る・44px は丸めずに比べる・縮める途中で失敗したら HK0 で作る・入れ替えるときは data-keys の外と hk- のキーを書かない（前の版の控えに入った a11y-v1 も）・drift-check は index.html の localStorage でも見て、SHELL はコメントを除いて、qa/run.mjs の checkTransfer も見る。
- [x] 見つける: scripts/check-transfer.mjs に「4MB を超える記録は書き出しで止める」「URL の途中で改行されたコードも読める」を足した。
- 見送ったもの（理由）：QR を読み取って中身を確かめる検査（読み取りの部品を足すほどではない。QR は qrcode-generator がそのまま作る）・古いブラウザ向けに HK0 を選ぶ画面（Safari 16.4 未満などはごく少ない）・保存に失敗して画面だけに残る記録の書き出し（ゲームごとの作り）。
- 残り：記録の中身の形（`days:null` など）は部品では見られない。正しい CRC で形の壊れた記録を作って渡されると、ゲームによっては開けなくなる（部首たし算の load() は `days` を補わない）。各ゲームの load() で入れ物の型を確かめる作業を別に起こす。

## 追記3（同じ日・きっぷで10 #9・しりとり最短 #7・間取りパズル #6・株ニュース #29 の版3へのレビュー）
- CodeRabbit が版3にも小さな抜けを指摘した：改行のあとの字下げでコードの後半が落ちる・記録が無いのにコードを作れる（受け取る側で必ず弾かれる）・ファイルを読み終える前に閉じる／別のファイルを選ぶと古い結果で確認の画面が開く・入れ替えも元に戻すのも失敗したとき、前の記録のただ1つの写しである控えを消していた。
- 原因：追記2と同じ。失敗の道（元にも戻せない・遅れて返る結果）を1つずつ足していて、「どの非同期の結果も、いまの画面のものか確かめる」「控えは、前の記録の写しがほかに無いあいだは消さない」という決まりで見ていなかった。
- [x] 直す: template/transfer.js を版4にした。改行のあとの空白・タブもまたいで読む・記録が無いと書き出さない・ファイルの読み取りにも番号を付け、画面を替えるたび（show）に番号を進める・元に戻せなかったときは控えを残し「控えに戻す」を知らせる。
- [x] 見つける: scripts/check-transfer.mjs に「改行のあとの字下げをまたいで読める」「コードのあとの空白と言葉は入れない」「記録が無いときは書き出さない」「元に戻せなかったときは控えを残す」を足した（版3では字下げの検査で落ちるのを確かめた）。
- 見送ったもの（理由）：圧縮が作れないとき「old」か「form」か（2件の指摘が逆のことを言う。今の「old」のままにする）・保存に失敗していた別のタブが、取り込んだあとに古い記録を混ぜ直す（ゲームの load() の合わせ方による。記録の形の検査と一緒に、各ゲームの作業として起こす）。
