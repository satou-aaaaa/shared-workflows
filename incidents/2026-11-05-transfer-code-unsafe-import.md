# 引き継ぎコードの部品が、作ったコードで画面にスクリプトを入れられる形だった

- 種類: 検査の見逃し
- 場所: template/transfer.js（版1）と、それを写したゲーム17本の PR（まだマージ前）
- 気づいた人: CodeRabbit（seiza-tsunagi #8・rosen-hitofude #9・kasane-zome #10・bento-zume #6・mannaka-kanji #7・tenkizu-yomi #7・amida-haitatsu #4 のレビュー）
- 影響: 公開前（どのゲームの main にも入っていない）。遊ぶ人への影響は無い。

## 起きたこと
- 2026-11-05 引き継ぎコードの PR に、CodeRabbit が3種類の指摘をした。
  1. 取り込む記録の中身を確かめていなかった。ゲームは記録の値（`ebest`・`total` など）をそのまま `innerHTML` に入れるので、`<img src=x onerror=…>` を入れて作ったコード・QR を他人に開かせると、確認の画面で「入れ替える」を押したあとにスクリプトが動く。同じサイトのほかのゲームの記録も読める。
  2. `data-keys` に、全部のゲームで分け合う見やすさの設定 `a11y-v1` を入れていた。取り込むと、ほかのゲームの設定まで変わる（書き出した端末に無ければ消える）。
  3. 入れ替えてから控えを書いていた。空きが足りず控えが書けないと、前の記録が戻せないのに「引き継ぎました」と出る。

## 原因
- 部品は「コードの形・CRC・キーの名前・値が文字か」だけを見て、中身は自分の端末で作ったものと思い込んでいた。コードは人から届くもの（外から入る値）として扱っていなかった。
- `a11y-v1` は「設定も一緒に移したほうが便利」と考えて足したが、同じ origin で分け合うキーだと考えていなかった。

## なぜ見つからなかったか
- 検査（scripts/check-transfer.mjs・qa/transfer-check.mjs）が、弾くコードとして「写しまちがい・別のゲーム・知らないキー・新しい版」しか作っていなかった。危ない中身・分け合うキー・空きが無いときを試していなかった。

## 対策
- [x] 直す: template/transfer.js を版2にした。記録のキーと文字の値に `< > " ' ` + "`" + ` があるコードを弾く・`data-keys` に `a11y-v1` があると動かない・控えを先に書き、書けなければ入れ替えない。17本の PR を版2に差し替え、`data-keys` から `a11y-v1` を外した。
- [x] 防ぐ: `routines/game-dev.md`「引き継ぎコード」に「コードは他人から届く。記録の値を画面に出すときは `Number()`・`esc()` を通す」「`a11y-v1` を入れない」を足した。
- [x] 見つける: scripts/check-transfer.mjs に「HTML の印の文字が入った記録のコードを弾く（値・キーの名前）」「`a11y-v1` を data-keys に入れると動かない」「控えを書けないときは入れ替えない」を足した。各ゲームの qa（template/qa/transfer-check.mjs）にも「HTML の印の文字のコードを弾く」を足した。

## 追記4（同じ日・条文討伐 jobun-tobatsu #6 の版4へのレビュー）
- CodeRabbit が版4の「控えに戻す」で記録が消える道を指摘した：戻す前に、控えをいまの記録で上書きしていた。そのあと入れ替えも元に戻すのも失敗すると、戻したかった記録（控え）のただ1つの写しが消える。#154 では「控えが1つなので片方しか残せない」として見送っていた。
- 原因：取り込むときと控えに戻すときを同じ手順（先に控えを書く）で書いていた。控えに戻すときは、控えこそが戻したい記録の写しなので、先に上書きしてはいけない。見送りを決めるとき、「どちらを残すか」をこの2つの場合に分けて考えていなかった。
- [x] 直す: template/transfer.js を版5にした（コードの形は変えないので、コードの版 `VERSION` は 4 のまま）。控えに戻すときは、入れ替えが済むまで控えに触らない。済んだら戻す前の記録を新しい控えにする（もう一度押すとまた入れ替わる）。途中で止まったときは控えがそのまま残り、知らせの「控えに戻す」でもう一度戻せる。入れ替えのあと新しい控えを書けないとき（空きが足りない）は、戻す前の記録の写しが無くなるので入れ替えを戻し「元のまま」と知らせる（#157 の CodeRabbit の指摘）。
- [x] 見つける: scripts/check-transfer.mjs に「控えに戻す途中で止まり元にも戻せなかったときも控えを消さない」「控えに戻せたら戻す前の記録が新しい控えになる」「新しい控えを書けないときは戻す前の記録に戻す」を足した（版4では1つ目が落ちるのを確かめた）。template/qa/transfer-check.mjs で、知らせの「控えに戻す」（#hk-toast-undo）を押して前の記録に戻ること・もう一度押すとまた入れ替わることを確かめるようにした（版4までは知らせのボタンがあることだけ見て、押していなかった）。
- [x] 防ぐ: `routines/game-dev.md`「引き継ぎコード」に「控えは、その中身の写しがほかに無いあいだは上書きしない（取り込むときはいまの記録、控えに戻すときは控えそのものが、ただ1つの写し）」を足した。

## 追記5（同じ日・条文討伐 jobun-tobatsu #7 の版5へのレビュー）
- CodeRabbit が、記録と控えがどちらも約3MBあって保存の上限（約5MB）に近いと、「控えに戻す」が新しい控えを書けずに毎回「元のまま」になる、と指摘した（Major）。
- 見送る（理由）：記録は消えない（入れ替えを戻して元の記録に戻る。版5で検査済み）。ゲームの記録は数KBで、上限の半分を超える記録は作れない（書き出しは4MBで止め、取り込みも同じ）。直すには、控えを書く前にいまの記録を消すなど「写しが1つも無い時」を作ることになり、追記4の決まり（ただ1つの写しは上書きしない）に反する。
- もし大きな記録のゲームを作るときは、控えを使わず書き出したファイルで戻す形にする。
