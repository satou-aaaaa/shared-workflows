# ひな形の全ゲーム配布を、2つのスレッドが別々の手元の写しから同時に進めていた

- 種類: 手順の抜け
- 場所: `scripts/sync-template.mjs`（手で全ゲームへ写すとき）
- 気づいた人: 新作を作るスレッド（ひな形 v13 #334 の配布を23本マージしたところで止めた）
- 影響: 手元の shared-workflows が origin/main より古いまま写すと、あとから main に入ったひな形の直し（store.js #358・depth.js 版5 #359 など）を古い写しで上書きした PR ができる。今回は止めたので、公開中のゲームには出ていない。

## 起きたこと
- ひな形 v13 の配布を、新作のスレッドが手元の写しから1本ずつ PR にしていた。同じころ、保存の共通部品と深さの版5の直しも別のスレッドが全ゲームへ写していた。
- どちらのスレッドも、写す前に手元の shared-workflows が main の最新か確かめていなかった。

## 原因
- sync-template.mjs は手元の template/ をそのまま写し、それが main より古くても止めなかった。
- 全ゲームへの配布は Template sync（main の最新から写す）に任せる決まりだったが、鍵が無いあいだは手で配っていた。

## なぜ見つからなかったか
- game-qa の sync-template --check は main のひな形と比べるので、古い写しの PR は QA で落ちる。ただし落ちるのは PR を開いたあとで、二重の作業が起きてから。

## 対策
- [x] 防ぐ: `scripts/sync-template.mjs` が写す前に origin/main を取り、手元のひな形が古ければ止める（終わりのコード 3。わざとなら SYNC_ALLOW_STALE=1。--check では見ない）（この PR）
- [x] 防ぐ: 全ゲームへの配布は `.github/workflows/template-sync.yml`（main の最新から写す）に一本化し、新作のスレッドの手の配布は止めた（2026-11-17）
- [x] 直す: 残りのゲームへは Template sync が配った（11/27 の配布で200本超。2026-11-27-core-helpers-left-in-games.md）。配り残しは週次まとめの「ひな形からのずれ」が毎週出す（11/28 土曜の見直しで閉じた）
