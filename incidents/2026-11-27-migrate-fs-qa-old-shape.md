# 文字の大きさを共通の設定へ移したら、2本のゲームの QA が前の形のまま試して落ちた

- 種類: 公開・CI
- 場所: `template/a11y/a11y.html`（A11y.fsFrom の前の値の読み方）・`scripts/sync-template.mjs`（migrateFs・migrateFsQa）・kusuri-yomi と otsukai-memo の `qa/run.mjs`
- 気づいた人: ダークモードのスレッドが、ひな形を写す PR の QA が落ちる8本を調べて見つけた
- 影響: 2026-11-27、くすりよみ・おつかいメモの2本で「ひな形の共通部品を写す」PR が QA で止まり、共通部品（成績・ダークモードなど）が届かなかった。遊ぶ人への害は無い（main は前のまま）。

## 起きたこと
- くすりよみの QA「文字の大きさ：1・2・3 以外（2.5 など）は大きいにもどす」が落ちた。前のゲームごとの値 `kusuri-fs=2.5` を、a11y の `A11y.fsFrom` が 1〜3 の範囲だからと受け入れ、文字の大きさの印が付かなかった。また QA は同じページで先に「とても大きい」を押しており、共通の値（a11y-v1 の fs）が前の値より勝っていた。
- おつかいメモの QA「文字の大きさを変えても a11y-read を消さない」が落ちた。QA は html に a11y-read を直に足して試すが、共通の設定を変えると見やすさの部品が印を付け直すので、直に足した印は消える。

## 原因
- `A11y.fsFrom` の前の値の読み方が、ゲームの fsGet（Number.isInteger で整数だけ）より甘かった。
- migrateFsQa が、QA の「class の名前」しか書きかえておらず、「前の値を入れて試す」「印を直に足して試す」形を共通の設定に合わせていなかった。

## なぜ見つからなかったか
- 移しを足した PR（#638）で手元の QA を回したのは7本だけだった。2本は 154 本の中で少数の書き方（範囲の外の値を試す・印を直に足す）だった。おつかいメモは見本に入っていたが、そのあと v10 で入れた検査の順に当たらなかった。

## 対策
- [x] 直す: a11y v11 で、前の値は 1・2・3 だけを使う。migrateFsQa が、前の値を入れて試す所で共通の値を消し、a11y-read を A11y.set で入れる形に書きかえる（この PR）。2本とも手元の QA が通った。
- [x] 防ぐ: check-a11y-block.mjs（Selftest）に「前の大きさが 2.5 なら既定の値」、check-kiroku.mjs（Lint）に migrateFsQa の書きかえを足した（この PR）。
- [x] 防ぐ: routines/game-dev-detail.md に「ゲームの関数や QA を書きかえる移しを足したら、書きかえる所の形を全ゲームで数え、形ごとに1本以上を手元で写して QA を回してからマージする」を足した（この PR）。
