# sandbox の法令の見張り（Law watch）が4週続けて落ち、法令の版の更新が知らされなかった

- 種類: 見回りの見落とし
- 場所: satou-aaaaa/sandbox の Law watch（毎週月曜）・監督の巡回
- 気づいた人: 「shared-workflows の充実」スレッド（e-Gov の回り道を調べていて見つけた）
- 影響: 10/5・10/12・10/19 の回がすべて赤。点検そのものは通っていた（e-Gov も取得失敗 0 件）が、結果の Issue が立たず、10/19 に見つかった法令の版の更新3件（産廃・特定技能）が届いていなかった。夜間検査・ミューテーションの知らせも同じスクリプトを使う。

## 起きたこと
- Law watch の最後の手順で `scripts/gh-upsert-issue.sh` を直接呼ぶが、git に実行の印（100755）が無く `Permission denied`（exit 126）で落ちていた。
- 10/19 に「CI失敗: Law watch（main）」の Issue が立ったが、3日間コメントも PR も付かなかった。

## 原因
- スクリプトを足したときに実行の印を付け忘れた。ワークフローが直接呼ぶスクリプトの印を見る検査が無かった。

## なぜ見つからなかったか
- 監督の巡回は sandbox の CI 失敗を「Issue/PR定期対応（週1）」に任せる決まりで、その回が拾わなかった。週1の定期実行は次に成功するまで Issue が閉じないので、開いたままの日数を見る仕組みが無いと、ほかの古い Issue に埋もれる。
- 週次まとめの「次にやること」は CI 失敗を並べるだけで、何日放っておかれたかを出していなかった。

## 対策
- [x] 直す: `gh-upsert-issue.sh` に実行の印を付けた（sandbox #297）
- [x] 防ぐ: sandbox の `test/workflowScripts.test.js` が、ワークフローが直接呼ぶ `scripts/*.sh` の印を見る。直す前の版で落ちることを確かめた（sandbox #297）
- [x] 見つける: `scripts/next-actions.mjs` が、3日以上開いたままの ci-failure Issue をいちばん上に「直されていない」として出す。監督の手順（supervisor.md 手順3）に、3日以上手つかずなら担当の回を待たずに直すスレッドを立てる、を足した
- [x] 防ぐ: 実行の印の壁と回り道を `routines/known-limits.md` に書いた
