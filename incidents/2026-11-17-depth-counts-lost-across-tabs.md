# 保存できないタブと保存できるタブが並ぶと、「自信あり」の通しの数が片方の分だけ消えていた

- 種類: 動作
- 場所: `template/depth.js`（版5）と、写した各ゲーム
- 気づいた人: CodeRabbit（recycle-mark #7）
- 影響: 保存に失敗しているあいだに別のタブで自信ありを数えると、保存できるようになったとき片方の数が消えた。実績（自信あり N 回）が少なく出る。★・遊べる量・今日のお題には影響なし。同じレビューで、ゲーム側の2つの小さな穴（作り直せない形の鍵を通す・別のタブで進んだあとに自信を先に数える）も見つかった。

## 起きたこと
- recycle-mark に depth.js を入れる PR #7 のレビューで、CodeRabbit が `read()` の合わせ方を指摘した。
- 控え（このタブの保存できなかった分）と保存済みの分を合わせるとき、数（sure・sureOk・learned）を `Math.max` で取っていた。

## 原因
- 数は「足していくもの」なのに、多いほうを取っていた。控えは「失敗した時点の保存済み＋このタブで足した分」なので、そのあとほかのタブが保存した分は、多いほうを取ると片方しか残らない。
- ゲーム側：`itOf` が `00|0|1` のような余分な0を許し、同じ問題が別の鍵で数えられた。`tap`・`solve` が `same()` を確かめる前に `Depth.judge` を呼び、読み直しになる回でも自信を数えていた。

## なぜ見つからなかったか
- `depth-check.mjs` の nosave は1つのタブだけで、2つのタブのうち片方だけ保存できない形を見ていなかった。
- 手順書は「最初に答えたとき judge」とだけ書き、別のタブで進んでいないかを先に見る順番を書いていなかった。

## 対策
- [x] 直す: 保存できないあいだに足した分（pend）を覚え、合わせるときは「保存済み＋足した分」にする（`template/depth.js` 深さの版 6・この PR）。`Depth.VERSION` も 3 のままだったので 6 に合わせた
- [x] 見つける: `template/qa/depth-check.mjs` に nosave-tabs（片方のタブだけ保存できない・両方の数が残る・二重に数えない）を足した。古い版では3つとも落ちることを確かめた（この PR）
- [x] 防ぐ: `routines/game-dev-detail.md` の「自信をかける」に、judge の前に `same()` で別のタブの進みを見る・鍵を作り直して同じ文字になるかで受ける、を書いた（この PR）
- [x] 直す: recycle-mark #7 で `itOf` と `tap`・`solve` を直した。ほかの depth の PR にも同じ形があれば同じ夜に直す（recycle-mark #7）
