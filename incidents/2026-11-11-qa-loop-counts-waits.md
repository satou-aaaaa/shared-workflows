# やりくり商店街の QA が、店主の番を待つ回まで回数に数え、遅い CI で「増築」の検査が落ちた

- 種類: 検査の見逃し
- 場所: satou-aaaaa/yarikuri-shotengai の `qa/run.mjs`（上級ルールの「増築する」の検査と `playOut`）
- 気づいた人: 見回り（coordinator）。PR #4 の CI
- 影響: PR #4（上級ルール）の QA が1件赤になり、マージが遅れた。手元では通っていた。遊ぶ人への影響は無い。

## 起きたこと
- 2026-11-11 17:01、PR #4 の QA で「上級：『増築する』から自分の店を押すと2階建てになり、盤に『2F』が出る」だけが落ちた（Ubuntu の置き場の障害が明けたあとの初めての実行）。
- 検査は `for (let k = 0; k < 80 && !up; k++)` で回し、店主の番のあいだは `{ await p.waitForTimeout(120); continue; }` で待っていた。

## 原因
- 待つだけの回も80回に数えていた。CI の機械は手元より遅く、店主が考える間（650ms）に何回も待つので、増築できる日まで進む前に回数が尽きた。
- 同じ PR の次の実行では「2人対戦を通しで遊ぶ」が、押せる札を待って時間切れになった。2人対戦の種は毎回ちがい、約5%の種（1万局で5.28%）では、はじめの3枚が全部はじめのお金（4💰）より高く、押せる札が無かった。
- そのうえ、人の手は毎回いちばん左の札を買うので、種によってはお金がたまらず、一度も増築できないまま終わることがあった（練習の種は毎回ちがう）。

## なぜ見つからなかったか
- 手元の機械は速く、80回で足りていた。種も毎回ちがうので、落ちる回に当たらなかった（どちらも、毎回ちがう種の画面で「いつもできるはず」の操作を当てにしていた）。
- 回数で区切るくり返しが待つ回まで数えているかを見る検査が無かった。

## 対策
- [x] 直す: 増築の検査は、自分の店があれば店番でお金をためて必ず増築まで進む形にし、くり返しは時間（90秒）で区切った。`playOut` も待つ回を数えず、120秒で区切った（yarikuri-shotengai #4）
- [x] 直す: 札を押す前に、買える札が出るまで店番で進める `toPick` を置いた（yarikuri-shotengai #4）
- [x] 防ぐ: `scripts/game-patterns.mjs` に `waitCounted` を足し、drift-check が `qa:wait-count` で「回数で区切るくり返しの中に、待つだけの回 `{ await p.waitForTimeout(…); continue; }` があり、時間で区切っていない」ゲームを週次まとめに出す。`scripts/check-game-patterns.mjs` に出す形・出さない形の例を足した（この PR。直す前の yarikuri-shotengai の2か所で出ること、今の全ゲームで0件のことを確かめた）
