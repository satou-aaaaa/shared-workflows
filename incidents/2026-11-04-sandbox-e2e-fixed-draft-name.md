# sandbox の E2E が、下書きの名前が固定のため、やり直すと必ず落ちていた

- 種類: 検査の見逃し
- 場所: satou-aaaaa/sandbox の `e2e/kobutsu-intake-form.spec.js` ほか（下書きを保存する E2E）
- 気づいた人: 手入れの少ないリポジトリを整える作業（main の Test の赤を見たとき）
- 影響: 2026-11-04 main の Test が1回赤になり、Agent revert が動いた（AGENT_GH_TOKEN が使えず何もせずに失敗）。再実行で ✅。本番（アプリ）の不具合ではない。

## 起きたこと
- 2026-11-04 sandbox #318 のマージ後の main の Test で、古物商の下書きの E2E が1回目「一覧に行が無い」で落ち、やり直し（`retries: 1`）で「同じ名前の行が2つ」（strict mode violation）で落ちた。

## 原因
- 下書きを保存する3つのテストが、固定の名前（「下書きE2Eテスト古物商」など）を使っていた。下書きは E2E の全テストで1つのファイルを共有し、あとで消さないので、やり直すと前の回の下書きが一覧に残る。やり直しが成功する道が無く、1回目の揺れがそのまま赤になっていた。

## なぜ見つからなかったか
- 混在のテスト（同じファイル）は `Date.now()` で一意な名前にしていたが、ほかの3つに同じ形を求める検査が無かった。ふつうは1回目で通るので、やり直しの道は一度も試されていなかった。

## 対策
- [x] 直す: 3つのテストの名前に `Date.now()` を付けた（sandbox #320）
- [x] 防ぐ: sandbox の `test/e2eHygiene.test.js` が、「下書きとして保存」を押すテストに `Date.now()`・`randomUUID()` があるかを見る。直す前の spec で落ちることを確かめた（sandbox #320）
