# 天秤の書の多肢選択式で、語群の並びから答えが分かった（正解が毎回1・5・9・13番目）

- 種類: 動作
- 場所: tenbin（天秤の書）行政書士の多肢選択式
- 気づいた人: satou さん
- 影響: 行政書士の多肢選択式19問すべて。本番形式模試では、語群の1・5・9・13番目を選べば全問正解できた

## 起きたこと
- 2026-11-05、satou さんが「多肢選択式の問題の選択肢が順番に並んでいて、答えを推測できてしまいます」と知らせた。
- 調べると、問題データの語群は「正解の語を、似た語4つのまとまりの先頭に置く」書き方で、19問とも正解が 1・5・9・13 番目だった。
- 練習画面は開くたびにかき混ぜていたが、本番形式模試の画面はデータの順のまま出していた。

## 原因
- 語群の並びをデータに任せていた。問題を書く人は、正解とそれに似た語をまとめて書くのが自然なので、データの順はいつも答えの並びになる。
- 画面ごとに並べ方を別々に書いており（練習はその場のかき混ぜ、模試はデータの順）、決まった並べ方が1つに決まっていなかった。社労士の選択式は前から問題ごとに決まった順（srWords）で出していたが、行政書士の側には入っていなかった。

## なぜ見つからなかったか
- CI の検査は、答えの番号と解説の数・文字の濃さ・表示のはみ出しを見ていたが、「出題の並びから答えが分かるか」は見ていなかった。
- 模試の検査（exam.cjs）は出題の数と順番を見ていたが、語群の中の並びは見ていなかった。

## 対策
- [x] 直す: 問題の id から決まる並べ替え gyOrder を足し、練習・模試とも同じ順で出す（tenbin #86・Artifact v126）
- [x] 防ぐ: 並べ方を1つの関数にまとめ、画面はデータの順を使わない。データの語群は好きな順で書いてよいことを部品の README に書いた（`tenbin/tashi/README.md`）
- [x] 見つける: CI の Check（`tools/check.mjs`）が、画面に出た語群で、データの順のまま・正解の位置が等間隔・続きの位置に固まる・3問以上で同じ位置・画面ごとに番号が違う、を落とす。新しい試験の語群問題も対象（tenbin #86）
