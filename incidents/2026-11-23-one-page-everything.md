# AI が作るページが、全部の中身を1ページに縦に積んで見づらかった

- 種類: 表示
- 場所: ゲーム・アプリ・紹介ページ全体（ひな形 `template/`・`routines/ui-rules.md`）
- 気づいた人: satou さん（2026-11-23「AI が作るページはペライチが多く、情報をすべて同じページに入れようとするため、見づらい」）
- 影響: 例として川越の防災アプリは1ページに見出し16個、川越散歩は9個。目的のちがう中身（調べる・備える・記録など）を縦に積み、探すのにスクロールが要った。

## 起きたこと
- ゲーム・アプリは単体の HTML で作り、画面を分ける共通の部品も決まりも無かった。AI は足す中身をページの下へ積んでいった。

## 原因
- 画面の切り替えはゲームごとに手で書くしかなく、いちばん楽な「下に足す」になっていた。
- 画面の決まり（U1〜U9）はホームの押せる数・重なりまでで、1画面の見出しの数・長さ・画面の分け方の決まりが無かった。

## なぜ見つからなかったか
- ui-check は押せる部品の数と重なりだけを数え、見出しの数・ページの長さを数えていなかった。

## 対策
- [x] 防ぐ: 共通部品 game-core v4 に画面の切り替え `Core.screens`（`<section data-screen>` を URL の # で1つだけ見せる。戻る・フォーカス・題）を足し、手で書かなくてよくした。動きは `scripts/check-screens.mjs`（Selftest）。この PR
- [x] 防ぐ: `routines/ui-rules.md` に U10〜U12（1画面に目的1つ・見出し5まで・長さはスマホ3画面分まで・行き先5まで・畳みは1段）と「ページの分け方」を足した。新しいゲームの形は `routines/game-dev-detail.md`「画面の分け方」。この PR
- [x] 見つける: `scripts/ui-check.mjs` が見出しの数・長さ・畳みの入れ子・画面の数を数え、画面を分けたページと `"pages": "fail"` では落とし、前からあるペライチは ::warning:: で知らせる。この PR
- [ ] 直す: 見本として川越の防災アプリ・川越散歩・ゲーム紹介サイトを画面に分ける（担当: 見やすいページの作り方を調べる スレッド、期限: 2026-11-30）
