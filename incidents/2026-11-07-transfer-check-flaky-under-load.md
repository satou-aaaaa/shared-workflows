# 引き継ぎの検査が、PC が重いときだけときどき落ちた

- 種類: 検査の見逃し
- 場所: template/qa/transfer-check.mjs（版11で足した検査。全ゲームの qa/transfer-check.mjs に写る）
- 気づいた人: 版11を全ゲームへ配っていた担当（4本ずつ同時に QA を回していたとき）
- 影響: 「止まったあとに遊んだ記録は、残った記録へ戻しても控えに残る」「古いタブの保存を捨てたら帯を出す」が、bento-zume・gogen-suiri・otsukai-memo・rekishi-narabe などで、ときどきだけ落ちた。回し直すと通る。ゲームの動きのまちがいではなく、検査の待ち方のまちがい。

## 起きたこと
- 2026-11-07、版11を配るために QA を4本ずつ同時に回すと、上の2つが数本に1回落ちた。1本だけで回すと15回続けて通った。

## 原因
- ゲームは読み込みのあと記録を整えて書き直す（`t` など）。検査は読み直しのあと 300ms だけ待って「戻す直前の記録」を取っていたので、重いとゲームの書き直しの前の記録を取り、控え（書き直しのあと）と食いちがった。
- 古いタブは保存を捨てると帯を出し、すぐ読み直す。検査は帯の有無を evaluate の返事で受け取っていたので、重いと返事より先に画面が読み直され、失敗あつかいになった。

## なぜ見つからなかったか
- 検査を作ったときは1本ずつ回し、重いときを試していなかった。決まった時間で待つ書き方を止める決まりが無かった。

## 対策
- [x] 直す: 比べる前に記録が落ち着くまで待つ `settle()` を足して、戻す直前の記録（nb・nb2・nb3）を取る所で使った。帯の結果は読み直しても残る sessionStorage に書いてから、読み直しのあとに読む（この PR）
- [x] 防ぐ: template/qa/transfer-check.mjs の頭に「待ち方の決まり」（決まった時間で比べない・読み直しを起こす操作の結果は sessionStorage に書く）を書いた（この PR）
- [x] 見つける: 直したあと、4本同時に回しながら otsukai-memo・kyuyo-meisai の `qa/run.mjs` が通ることを確かめた。各ゲームへは次に写すときに届く（game-qa の「ひな形の写し」が、写しを直した PR で main のひな形と同じかを見る）
