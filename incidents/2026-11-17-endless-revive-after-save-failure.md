# 保存に失敗したあと、終えたとことんが読み直しで古い途中経過に戻る形が、ゲームに広く写っていた

- 種類: 動作
- 場所: satou-aaaaa のゲームの index.html の load()（手元にある19本で確認。dashisugi-check などから写した形）、mizu-mamoru
- 気づいた人: CodeRabbit（mizu-mamoru #1）
- 影響: 端末の容量不足などで保存に失敗しているあいだに、保存済みのとことんを終えると、次に記録を読み直したとき古い回が戻る。「もう一度とことん」が終えた回の続きになる。保存に失敗したあいだだけで起き、報告は無い。

## 起きたこと
- load() は、保存に失敗したあと、メモリ（新しい）と localStorage（古い）を合わせる。片方の途中経過が null のとき、日ごとの記録に入っていなければ、もう片方の途中経過を残す。
- とことん（mode "e"）は日ごとの記録が無いので、新しいほうで null（終えた）でも、古いほうの途中経過が必ず戻る。
- 2026-11-17 mizu-mamoru #1 で CodeRabbit が指摘した。この形は写し元の dashisugi-check ほか手元の19本にもあった。

## 原因
- 合わせる決まりが「日ごとの記録に入ったか」だけで終わりを見分けていて、日ごとの記録を持たないとことんの「終えた」を表すのが null しか無かった。
- index.html はひな形に無く近いゲームから写すので、写し元の形がそのまま広がった（2026-11-17-known-game-bugs-spread.md と同じ道筋）。

## なぜ見つからなかったか
- 各ゲームの QA は、保存に失敗する検査を「帯が出るか」でしか見ておらず、失敗したあとに終えた回を読み直す道を通していなかった。

## 対策
- [x] 直す: mizu-mamoru で、新しいほうが null のとことんは古い途中経過で戻さないようにし、QA に「終えた保存が失敗しても戻らない」を足した（mizu-mamoru #1）
- [x] 防ぐ: `scripts/game-patterns.mjs` の playerBugs に endless:revive を足し、ゲームの PR が新しく持ち込んだら game-qa の「遊ぶ人が困る作り」で落とす（この PR）
- [x] 見つける: drift-check でも endless:revive を出す（`scripts/drift-check.mjs`、この PR）
- [ ] 直す: すでにある各ゲームを mizu-mamoru と同じ1行に直す（担当: 新作ゲームを作る(並列3)、期限: 2026-11-24）
