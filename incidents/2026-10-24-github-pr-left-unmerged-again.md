# last-tell の QA ❌ を直す PR が、検査は緑のまま2日マージされなかった

- 種類: 見回りの見落とし
- 場所: satou-aaaaa/last-tell（PR #150・Issue #151）・Auto merge（共通部品）・監督の巡回
- 気づいた人: 監督の巡回
- 影響: 10/22〜24 の2日、main の QA が ❌ のまま（Issue #151 が開いたまま）。CI の入れる段階で止まる対策と perf 検査の揺れ止めが main に入らなかった。

## 起きたこと
- 10/22 13:28、main の QA で「fuzz 3/3（英語）」の組が apt-get update で60分止まり、Issue #151 が開いた。
- 同じ日、last-tell の担当が直す PR #150（.github/workflows/qa.yml・playthrough.yml と qa/checks/perf.js）を出し、14:13 に全検査が緑になった。
- #150 は .github/ を変えるので Auto merge が「手でマージ」とログに書くだけで止まり、出した担当もマージせずに次の作業へ移った。
- 10/24 の巡回で見つかり、別スレッドが中身を確かめて squash マージした。

## 原因
- Auto merge は .github/ を変える PR を飛ばすとき、ログに1行書くだけで、PR にもラベルにも何も残さなかった。PR の画面では「緑・mergeable」に見え、マージ待ちだと分からなかった。
- 手順（pr.md 5）は「緑なら手でマージする」とだけあり、誰がいつマージまで持つかが決まっていなかった。担当は PR を出した時点で次の作業に移れた。

## なぜ見つからなかったか
- 同じ日に同じ種類（carcassonne-research #69）を記録したが、その対策は「CI失敗の知らせに直す PR を書き添える」で、#151 は対策より前に開いた Issue なので書き添えが付かなかった。
- 監督の手順5は「緑のまま3日以上」で促す決まりで、2日目の #150 はまだ対象外だった。30日に同じ種類が2件で、一つずつの対策では足りていない。

## 対策
- [x] 直す: last-tell #150 を中身（apt に時間切れとやり直し・perf の揺れ止め・`Closes #151`）を確かめてマージし、main の QA を回した
- [x] 防ぐ: 共通部品 `automerge.yml` が .github/ を変える PR にラベル「手でマージ」と一言を付ける。`labels.yml` にもラベルを足した（この PR）
- [x] 防ぐ: pr.md 5 に「手でマージが要る PR は出した担当が subscribe_pr_activity で見張ってマージまで持つ。終わる前に自分の開いた PR を確かめる」を足した（この PR）
- [x] 見つける: 監督の手順3で、毎回の巡回でラベル「手でマージ」の PR を探し、6時間たったものをマージに回す（`routines/supervisor.md`）
