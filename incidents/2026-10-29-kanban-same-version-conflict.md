# カンバンのアプリ版で、並行した2つの PR が同じ版 v57 を取り、片方が main とぶつかって1日半止まった

- 種類: 検査の見逃し
- 場所: カンバンのアプリ版（local-kanban）の点検の記録の検査（qa/check-review.mjs）と自動マージ
- 気づいた人: 全リポジトリの巡回
- 影響: 会話・🎤で日付つきでカードを足す機能と、返事の題からカードを開く機能（PR #82）が、検査はすべて ✅ のまま 10/28 03:04 から 10/29 まで公開されなかった。

## 起きたこと
- 10/28、PR #81 と #82 が同じ main（v56）から作られ、どちらも sw.js の CACHE を v57 に上げ、reviews/v57.md を書いた。
- 両方の QA が通り、#81 が先に自動マージされた。#82 は sw.js・reviews/v57.md で main とぶつかり、マージできない状態になった。
- その後 main は v58 まで進んだが、#82 はだれも気づかず開いたままだった。10/29 に巡回が見つけた（Issue #87）。

## 原因
- check-review.mjs は「版が PR の元（base）より上がっているか」だけを見ていた。同じ元から作った2つの PR が同じ版を取っても、両方通った。
- 版の番号は「main の次」を各 PR が自分で決める作りで、並行して作ると同じ番号を取りうる。

## なぜ見つからなかったか
- QA は PR を作った時点の元と比べるので、ほかの PR が先にマージしても結果は ✅ のままだった。
- ぶつかりはほかの PR のマージで後から起きるので、自動マージの共通部品が回る時点（QA が終わったとき）には起きておらず、何も知らせなかった。

## 対策
- [x] 直す: #82 を今の main（v58）の上で v59 として作り直した（sw.js の CACHE・reviews/v59.md・reviews/README.md の次の候補）。
- [x] 防ぐ: check-review.mjs が、PR の版が今の main（先に git fetch した origin/main）の版より大きいかも見る。同じなら「main を取り込み次の空き版へ付け直す」と出して落ちる。この検査そのものを、仮のリポジトリで #81・#82 の形を作って試す qa/check-review.test.mjs を足し、QA で毎回回す（GitHub の「マージ前にブランチを最新にする」と同じ考え：PR を今の main と比べる）。
- [x] 見つける: ぶつかって止まった PR は全リポジトリの巡回（`routines/repo-patrol.md`）が拾う（今回もそれで見つけた。Issue #87）。ぶつかったときの直し方は `routines/pr.md` の「連番がぶつかったら後から直す側を次の空き番号に」。作り直しの push で QA が回れば、上の検査が版の重なりを知らせる。
