# carcassonne-research の selfplay が、試行番号が 1000 を超えたとたん学習データを消して落ちた

- 種類: 動作
- 場所: carcassonne-research の selfplay（自己対戦ループの学習と、古いデータの片付け）
- 気づいた人: 共通部品 ci-failure-issue（Issue #141）と見回り
- 影響: 11/06 の定期の回が赤。試行1000〜1002 の学習に、その試行の自己対戦データが入っていなかった（3回とも不採用なので、チャンピオンと公開ページへの影響はない）。約5時間分の自己対戦がむだになった。

## 起きたこと
- 自己対戦データの名前は `a{試行:03d}_{塊}.npz`。11/05 ごろ試行が 1000 になり、名前が4桁（`a1000_00.npz`）になった。
- 学習（`load_window`）と片付け（selfplay.yml の `run:` に直接書いた Python）は、名前を `name[1:4]` で切って番号にしていたので、`a1003` を 100 と読んだ。
- 片付けは新しいデータを古いと見て毎回消し、学習は残っていた 999 のデータだけで回った。999 も消えた試行1003 で、学習のデータが0件になり `ValueError` で落ちた。

## 原因
- 番号の桁が増えることを考えず、名前を決まった幅で切っていた。`:03d` は「3桁以上」の意味なのに、読む側は「ちょうど3桁」と決めていた。
- 同じ読み方を2か所（モジュールとワークフロー）に別々に書いていた。

## なぜ見つからなかったか
- テストは試行1〜2しか動かしていなかった。数が育って桁が変わる所（999→1000）を通るテストが無かった。
- 片付けはワークフローの `run:` に直接書かれ、テストからは一度も動いていなかった（11/04 の記録と同じ形の穴。あのときは gh を呼ぶ手順だけを動かす検査にした）。

## 対策
- [x] 直す: 番号は正規表現で取り（`data_attempt`）、並びも数の順にした。学習の番なのにデータが欠けていたら、落ちずに自己対戦からやり直す。いまの止まった状態も次の回で立ち直る（carcassonne-research #142）
- [x] 防ぐ: 片付けを `scripts/selfplay_loop.py prune` にまとめ、ワークフローはそれを呼ぶだけにした。読み方が1か所になり、テストから動く（carcassonne-research #142）
- [x] 防ぐ: 999→1000 をまたいで、学習の範囲と片付けを確かめるテストを足した（`tests/test_selfplay_loop.py`、carcassonne-research #142）
- [x] 見つける: `name[1:4]` のように名前を決まった幅で切る書き方を、src・scripts・workflows から探して落とすテストを足した（`test_data_names_are_not_cut_at_fixed_width`、carcassonne-research #142）
- [x] 防ぐ: 再発防止の手順（saihatsu-boushi の控え）の「原因」に、数が育つもの（通し番号・件数・日付）は桁や上限をまたぐ所をテストで通す、と足した（この PR）
