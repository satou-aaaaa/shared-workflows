# 引き継ぎコードの「控えに戻す」で、いまの記録が消えうる作りが残っていた

- 種類: 検査の見逃し
- 場所: `template/transfer.js`（引き継ぎの版10）と、それを写したゲーム
- 気づいた人: nijushi-sekki #4・meirei-narabe #4・taiyokei-kurabe #6 の CodeRabbit（版10を写した PR）
- 影響: まれな順番（控えに戻す途中で止まる・そのあと遊ぶ・別のタブを開いたまま）で、いまの記録がどこにも残らないことがあった。実際に消えた報告は無い。

## 起きたこと
- 2026-11-07、版10を3つのゲームに写した PR で、CodeRabbit が transfer.js に Major を3件出した（shared-workflows #219 にまとめた）。
  1. 前に途中で止まって残った `hk-prev:` が壊れていると、それを控えにして、いまの記録が消える。
  2. 途中で止まったあとに遊んで記録が変わっても、残った記録へ戻すときに控えを書かないので、あとから遊んだ分が消える。
  3. 古いタブの保存は黙って捨てて読み直す。読み直しが遅れる・止まると、そのあいだの保存はゲームには成功に見えて消える。
- あわせて Minor：入れ替えに失敗しても番号（`hk-sync:`）が進んだままで、ほかのタブの保存が捨てられる・`location.reload()` が例外で止まると、二度と読み直さない・検査の「取り込みの書き込みが失敗したら記録は元のまま」が、キーが無いと何も見ずに通る。

## 原因
- 版10で「途中で止まったら残った記録を使う」道を足したが、その記録が壊れている・そのあと記録が変わった場合を考えていなかった。
- 古いタブの保存を捨てる道は、すぐ読み直す前提で、知らせを出していなかった。

## なぜ見つからなかったか
- `template/qa/transfer-check.mjs` は、止まらずに進む道と、1か所の書き込みが失敗する道だけを見ていた。止まったあとの状態（残った記録が壊れている・記録が変わった）を作る検査が無かった。
- 失敗させる検査が、失敗させるキーが無いときに何も見ずに通る形だった（`wantVal === undefined ||`）。

## 対策
- [x] 直す: 引き継ぎの版11。壊れた `hk-prev:` は使わずいまの記録から作り直す・止まったときの記録の印（`hk-prevfp:`）とちがえば、戻すときにいまの記録を控えにする・入れ替えに失敗したら番号を戻す・古いタブの保存を捨てたら帯（`#hk-stale-tab`）で知らせる・読み直しが例外で止まったら次の保存でまた読み直す（この PR）
- [x] 防ぐ: `template/qa/transfer-check.mjs` に、残った記録が壊れている・止まったあとに記録が変わった・控えを書けず入れ替えなかったときの番号・古いタブの帯・止まったあとに別の記録を取り込んだときの控え（akushitsu-miyaburi #4）の5つの検査を足し、失敗させる検査は取り込む記録にあるキーで失敗させ、無ければ通さない形にした。版10ではこの4つが落ち、版11で通るのを kengen-check で確かめた（この PR）
- [x] 見つける: ゲームに写すと、どのゲームの QA でも同じ検査が回る。版10のままのゲームは `scripts/drift-check.mjs` の `transfer:version` が週次まとめに出す
