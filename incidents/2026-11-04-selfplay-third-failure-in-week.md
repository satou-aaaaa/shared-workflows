# carcassonne-research の selfplay が1週間で3回、本番でしか動かない手順で落ちた

- 種類: 公開・CI
- 場所: carcassonne-research の selfplay・AI content（自己対戦のあとの「差し替え・知らせ」の手順）
- 気づいた人: 共通部品 ci-failure-issue（Issue #118・#125）と見回り
- 影響: selfplay が 10/28（#92）・11/02（#110）・11/03（#118）に赤。どれもチャンピオンの採用・対戦ページの差し替えは済んでいて、抜けたのは知らせの Issue か PR だけ。AI content（#125）はコツ集の言い切りが外れて1回止まった。

## 起きたこと
- 10/28：もう main に入っていた差し替えを PR にしようとして「差が無い」で失敗（2026-10-28-queued-run-empty-pr.md）。
- 11/02：採用の知らせの本文が 65536 文字を超えて失敗（2026-11-02-selfplay-issue-body-too-long.md）。
- 11/03：採用の知らせのあと、前の知らせを閉じる `gh issue close` が API の 504 で失敗（2026-11-03-carcassonne-auto-pr-ci-noise.md）。同じ日の AI content は「草原でも多く取る」の言い切りが外れて止まった。
- 11/03 の2件の直し（gh_retry.sh・言い切りが外れても止めない）は同日 #121 で main に入っていたが、失敗はその前のコミットの実行だったので、Issue は開いたままだった。

## 原因
- 3回とも、約5時間の自己対戦のあと・採用が出た回にしか動かない手順で起きた。採用は数日に1回なので、手順を書き換えても、本番で採用が出るまで一度も動かない。
- その手順はワークフローの `run:` に直接書かれ、テストからは呼ばれていなかった。

## なぜ見つからなかったか
- 毎回の対策が「その症状だけを見る静的な検査」だった（#112 は `--body-file` の前に cap_body.py があるかを grep、#121 は gh の前に ghr があるかを grep）。手順そのものは一度も動かしていなかったので、次の別の症状（差が無い→長すぎ→504）は防げなかった。
- 11/02 の記録は「前回はその部分全体を見直していなかった」と書いたが、入れた対策はやはり1症状分で、部分全体を動かす検査にはならなかった。

## 対策
- [x] 直す: 504 のやり直しと、言い切りが外れても止めない作りは #121 で入済み。11/04 に今の main で AI content を回し直した（selfplay は次の定期の回で確かめる。成功すると Issue は自動で閉じる）
- [x] 防ぐ: selfplay・AI content の gh を呼ぶ手順を、ワークフローの `run:` そのままで毎回の PR で動かす `tests/test_workflow_rehearsal.py`。にせものの gh は本物の上限（本文 65536・題 256 文字）を守り、書き込みの1回目に 504 を返す。#110 の形に戻すと落ちることを確かめた（carcassonne-research #126）
- [x] 防ぐ: gh を呼ぶ手順を足して、この検査に入れ忘れるとテストが落ちる（`test_every_gh_step_is_rehearsed`、carcassonne-research #126）
- [x] 見つける: ワークフローの書き間違いを PR で止める actionlint のジョブを test.yml に足した（11/03 の記録の残り、carcassonne-research #126）
- [x] 防ぐ: 再発防止の手順（saihatsu-boushi の控え）の「繰り返し」に、同じ場所で2回目なら症状ごとの検査でなく、その場所を本番と同じ中身でにせものの相手と通しで動かす検査を入れる、と足した（この PR）
