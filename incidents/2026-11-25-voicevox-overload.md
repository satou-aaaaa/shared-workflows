# 解説動画の音声づくりが同時に15本走り、VOICEVOX が1回90秒待ちになった

- 種類: 手順の抜け
- 場所: 小江戸ゲーム部の解説動画（PC の VOICEVOX エンジン・共通の make_voice.py）
- 気づいた人: 解説動画のスレッド
- 影響: audio_query 1回が約89秒。15本ぶんの音声づくりがどれも進まなくなった

## 起きたこと
- 2026-11-25、解説動画の企画が一度に増え、各スレッドが自分の作業フォルダで make_voice.py を起動した。
- PC の VOICEVOX は 50022 の1つだけ。約15本が同時に投げたため、どの要求も列に並んで1回90秒近くかかるようになった。

## 原因
- make_voice.py は1本で動く前提で、何本走っているかを知るしくみが無かった。
- スレッドを並行に動かす決まり（11/25 の PARALLEL OK）に対して、PC の1つしかない道具を共有する側の決まりが無かった。

## なぜ見つからなかったか
- 検査は出来上がった動画を見るもので、作っている途中の混み具合は誰も見ていなかった。1本ずつなら速いので、起動する側からは遅れの理由が分からなかった。

## 対策
- [x] 直す: 走っている分はそのまま終わらせた（止めると作り直しになる）
- [x] 防ぐ: 共通の `make_voice.py` に順番待ちを入れた。`_common\voice_slots\` のロックを取れた2本だけがエンジンを使い、ほかは10秒ごとに空きを見て待つ。待ち時間を画面に出す。本数は環境変数 `VOICE_SLOTS` で変えられる
- [x] 防ぐ: 落ちたプロセスのロックは、PID が居ない・10分更新が無いことで回収する（消さずに脇へ名前を変え、同時の回収でも1本だけが取れる）。回収の跡は1日で片づける（`make_voice.py` の take_slot・stale）
- [x] 見つける: 4本同時に起動して、同時に持たれるロックが最多2つであること、待った側が「順番が来た（10秒待ち）」と進むこと、死んだ PID のロックが回収されることを確かめた（`make_voice.py` の順番待ちの試し）
- [x] 防ぐ: 共通フォルダの `README.md` に「同時に2本まで」を書いた
- [x] 防ぐ: PC の共通フォルダ `_common` へ新しい `make_voice.py` と `README.md` を写した（md5 がクラウドと一致）
- [x] 防ぐ: 各作業フォルダに残っていた古い make_voice.py（38ファイル）を、実行すると「共通版を使って」と出て止まるだけの `make_voice.py`（stub）に置きかえた。元は `.old` で残した（satou さんがカードで決定）
