# 新しく作ったアプリに共通の CI 部品が無く、1本は一覧にも無かった・共通の画面検査が何も数えていなかった

- 種類: 手順の抜け
- 場所: `repos.txt`・各アプリの `.github/workflows/`・共通部品 `ui-check.yml`
- 気づいた人: satou さん（2026-11-23「すべてのプロジェクトで使われる共有のものが反映されていないアプリがないかチェック」）。点検は Claude（全216本を clone して drift-check・sync-template --check・ホームの計測）
- 影響: たべたメモ・川越さんぽ・川越 避難ガイド・ゲーム一覧・Akashi の5本で、CI の失敗を Issue にする部品（ci-failure-issue）・ブランチの片付け・ラベルなどが無かった（main で落ちても誰も気づかない）。川越 避難ガイドは repos.txt に無く、週次まとめ・ずれの検査・巡回のどれにも出ていなかった。共通の画面検査 ui-check は172本で呼ばれていたが、設定ファイルが無いと何も数えずに通っていた。ゲーム200本は共通部品（見やすさ・game-core・引き継ぎ・感想フォーム・練習の1問）が全部入っていた。

## 起きたこと
- ゲーム以外のアプリは、Create repo のひな形でなく手で作り、手順書（onboarding.md 手順2）の「template/.github/workflows/ をコピー」を一部だけ行った。
- ずれの検査（drift-check）は週1の週次まとめの中だけで動き、前回は 11/16。11/21〜22 に作ったものは拾われず、出ても数百行の中に埋もれていた。

## 原因
- 「部品そのものが無い」という重い抜けと、「版が古い」などの軽いずれを、同じ週1の長い一覧に混ぜていた。作ってすぐの抜けを短い間に知らせる仕組みが無かった。
- ui-check は「基準が無ければ数えるだけ」の作りで、基準を作る手順がどこにも無かったので、入れても何も止めていなかった。

## なぜ見つからなかったか
- 週次まとめのずれは400行を超え、毎週同じ行が並ぶので読まれなくなっていた。
- ui-check の結果は ✓ と同じ見た目（落ちない）だった。

## 対策
- [x] 直す: 5本に共通の CI 部品を足した（tabeta-memo #7・kawagoe-sanpo #2・kawagoe-bousai #3・games #2・akashi-lang #22）。repos.txt に kawagoe-bousai（shared-workflows #582）。
- [x] 見つける: `.github/workflows/common-check.yml`（毎日 7:43 JST）が、部品そのものが無い行だけ（`scripts/drift-check.mjs` の DRIFT_ONLY）と、ホームの画面の決まりの違反を、Issue「共通部品の抜け」「画面の決まりの違反」にまとめ、無くなれば閉じる。
- [x] 防ぐ: `scripts/ui-check.mjs` に決まり U1〜U4（固定の部品で隠さない・同じ入口を二重に出さない・ホームはスマホで18まで・はみ出さない）を足し、基準が無くても落とす。設定ファイルが無いときもホームを測る（`--default`）。決まりの本文は `routines/ui-rules.md`。
- [x] 防ぐ: drift-check は、1本も見られなかったのに「ずれは見つかりませんでした」とだけ言わない（`scripts/drift-check.mjs`）。
