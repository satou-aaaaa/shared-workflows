# QA の検査が、このゲームに無い問題 id を使っていて何も確かめていなかった

- 種類: 検査の見逃し
- 場所: shukujitsu-yurai・hyakunin-awase の `qa/run.mjs`（onpu-yomi から写した検査）
- 気づいた人: CodeRabbit（shukujitsu-yurai #1）・QA（hyakunin-awase #4）
- 影響: 2026-11-07 に2回。遊ぶ人への影響は無い。検査2つが、通っても何も確かめていなかった。

## 起きたこと
- 祝日の由来の QA は、音符よみの QA を写して作った。「難しさと問題の合わないタグは作らない」は `G.make("0:y40|…")` が例外を出せば通る。音符よみには y40 があるが、祝日の由来の入力問題は y0〜y15 だけ。y40 が無いという理由で例外が出て、難しさの照合を消しても通る形だった。とことんの「前の回の最後の問題から始めない」も、無い y40 を渡していて何も比べていなかった。
- 同じ日、百人一首あわせの新しい検査で、1字決まりの87番に「決まり字あて」（2字決まり以上だけ）の id `r87` を書き、練習の回が捨てられて検査が止まった。

## 原因
- 検査に問題 id を文字で書いていた。id はゲームごとに作り方がちがい、写した先・データを変えた後にその id があるとはかぎらない。
- 例外を待つ検査は、「無い問題」で出た例外と、確かめたい理由で出た例外を分けない。

## なぜ見つからなかったか
- 検査は通っていた（通る理由がちがうだけ）。写すときに id がそのゲームにあるか確かめる手順が無かった。

## 対策
- [x] 直す: shukujitsu-yurai（#1）と hyakunin-awase（#4）の検査を、G.POOL から選んだ id にした
- [x] 防ぐ: `routines/game-dev.md` の QA の行に「検査で使う問題 id は文字で書かず、データから選ぶ」を足した
- [x] 防ぐ: `scripts/drift-check.mjs` に `qa:literal-id` を足した。例外を待つ検査（`try { make("0:y40|…") }`）に id を文字で書いた qa/run.mjs を週次まとめに出す（いまの onpu-yomi・kyukoku-mei・hyakunin-awase は、各ゲームの次の PR で直す）
