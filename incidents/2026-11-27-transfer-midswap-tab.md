# 引き継ぎコードで、入れ替えの途中に開いたタブや、戻す途中の二重の失敗で記録が消えうる作りが残っていた

- 種類: 検査の見逃し
- 場所: `template/transfer.js`（引き継ぎの版14）と、それを写したゲーム。あわせて `template/parts/index/cal.js`
- 気づいた人: kawagoe-1day #1 の CodeRabbit（Major 2件・Minor 2件）
- 影響: まれな順番で、取り込んだ記録が古い記録で上書きされる・遊んだ記録がどこにも残らないことがあった。実際に消えた報告は無い。カレンダーは出題数が5問でないゲームでも「その日の5問」と案内していた。

## 起きたこと
- 2026-11-27、新作 kawagoe-1day の PR で CodeRabbit が transfer.js に Major を2件出した。
  1. 入れ替えでは番号（`hk-sync:`）を進めてから記録を書き換える。そのあいだに開いたタブは「新しい番号」と「古い記録」を持つので、あとでその古い記録を保存でき、知らせも出ない。
  2. 控えに戻す途中で止まって `hk-prev:` が残ったあとに遊ぶと、いまの記録はメモリにしか無い。戻したあと控えの書き込みも書き戻しも失敗すると、その記録がどこにも残らない。
- Minor：カレンダー（共通部品 cal）が出題数を「5問」と決めつけていた（kawagoe-1day は3組）。QA の「入れ替えの前に開いたタブ」の検査は、保存を試したかを確かめずに通りうる。

## 原因
- 番号を「書き換えの前」に1回だけ進めていた。番号を読んだ時と記録を読んだ時のあいだに書き換えが入るタブを考えていなかった。
- 版11で「止まったあとに遊んだ分は控えにする」を足したが、控えにするのは戻したあとで、それまでの写しを localStorage に置いていなかった。
- 部品 cal は、ゲームごとにちがう出題数を文言に書いていた。

## なぜ見つからなかったか
- `scripts/check-transfer.mjs` は、思いついた止まり方を1つずつ作る検査だけで、書き込みの失敗の組み合わせ（控えも書けず、元にも戻せない、など）を網羅していなかった。版10〜14で同じ種類の指摘（記録が消えうる順番）が CodeRabbit から6回続いていた。
- タブの検査は「入れ替えの前に開いた」と「後に開いた」だけで、「途中で開いた」を作っていなかった。

## 対策
- [x] 直す: 引き継ぎの版15。番号は書き換えの前（`.w`）と書き換え終わったあと（同じ長さの `.d`）の2回進める・戻す先とちがういまの記録は、戻す前に `hk-next:<ゲーム>` に書き、書けなければ戻さない（`readBackup` はこれも控えとして出す）・カレンダーの案内を「その日の問題」にした（この PR）
- [x] 防ぐ: `scripts/check-transfer.mjs` に、書き込みの失敗をあらゆる組み合わせ（最初の9回の書き込みの全部の組 512 通り × 8 つの場面）で起こし、前からあった記録が記録か控えのどこかに残るかを見る検査を足した。版14ではこの検査が5場面で落ち、版15で通る。途中で開いたタブの検査（`.w` の番号のタブは書き換え後に保存できない）も足した（この PR）
- [x] 防ぐ: 部品を直すと1字も同じでなくなり、まだ印の無いゲームに届かなくなる。前の版を `template/parts/<種類>/old/` に置くと `migrateParts` が前の版の写しにも印を付けて新しい版に替える。`scripts/check-parts.mjs` がこれと「カレンダーが問題の数を決めつけない」を見る（この PR）
- [x] 見つける: `template/qa/transfer-check.mjs` の古いタブの検査は、保存を試した印を sessionStorage に書き、その印があることも別に確かめる（この PR）。写したゲームの QA で毎回回る。版14のままのゲームは `scripts/drift-check.mjs` の `transfer:version` が週次まとめに出す
