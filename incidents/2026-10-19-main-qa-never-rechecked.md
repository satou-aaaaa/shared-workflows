# last-tell の「CI失敗: QA（main）」が、直ったあとも2日間閉じず、再実行しても赤のままだった

- 種類: 公開・CI
- 場所: satou-aaaaa/last-tell（同じ作りの naitei-no-michi・local-kanban も）、共通部品 automerge・ci-failure-issue
- 気づいた人: 監督の巡回（satou さんの指示で再実行）、TODO ボード
- 影響: last-tell #71 が 10/17 から開いたまま。再実行に 16 ジョブ分の時間を使い、担当を探す手間がかかった。

## 起きたこと
- 2026-10-17 14:30 UTC、手でマージした PR（.github/ を変える CI の高速化）で main の QA が回り、v0.91.2 の画面の重なり1件で ❌。#71 が立った。
- そのあとの版（v0.92〜v0.96.4）は自動マージで公開され、PR の QA はすべて ✅ だった。
- 2026-10-19 06:05 UTC に #71 の実行を再実行したが、同じ古いコミット（v0.91.2）を検査したので同じ組が赤のまま。

## 原因
- 自動マージは GITHUB_TOKEN でマージするので、main への push で他のワークフローが動かない（GitHub の仕様）。公開とタグは dispatch で起こしていたが、QA は main で一度も回らなかった。
- ci-failure-issue は「同じワークフローが main で次に成功したら閉じる」作りなので、main の QA が回らない限り閉じない。
- 再実行は、そのときのコミットのまま回る。直ったかどうかは今の main で回さないとわからない。

## なぜ見つからなかったか
- Issue の本文に「再実行すれば閉じる」と読める書き方しかなく、古いコミットだと気づく手がかりが無かった。
- 自動マージの部品の説明に、main で見張っている検査（QA）も起こし直す必要があることが書かれていなかった。

## 対策
- [x] 直す: 今の main（v0.96.4）で QA を手で回し、#71 を閉じた。#78（通しで遊ぶ）は 10/18 から2回続けて ✅ なので閉じた
- [x] 防ぐ: automerge にマージ後の `recheck_main`（既定 true）を足し、きっかけの検査を main でも回す（このPR。last-tell・naitei-no-michi・local-kanban に呼び出し側の変更なしで効く）
- [x] 防ぐ: last-tell の `.github/workflows/playthrough.yml` が、✅ のときに開いている「通しで遊ぶ検査が ❌」を閉じるようにした（last-tell の PR）
- [x] 見つける: ci-failure-issue が、古いコミットの実行（再実行など）で赤になったときは「今の main の先頭ではない、main で回して確かめる」と Issue に書き添える（このPR）
