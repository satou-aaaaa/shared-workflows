# はじめて開くと、まだ長い「遊び方」の窓が出るゲームが残っていた

- 種類: 手順の抜け
- 場所: 各ゲームの `index.html`（home() の `if (!s.tut) openHow();`）
- 気づいた人: satou さん（2026-11-22「まだ『遊び方』が最初にでているものがある」）
- 影響: 震度よみ以外の約190本で、はじめての人に長い説明の窓が先に出ていた（11/21 に「練習1問＋吹き出し」を選んだが、試しの1本にしか入れていなかった）。

## 起きたこと
- 共通部品（Core.coach）は全ゲームに配ったが、はじめての練習の流れ（どの練習を始め、どこに吹き出しを付けるか）はゲームごとに手で書く前提で、震度よみの1本にしか入れていなかった。

## 原因
- 「部品を配る」と「各ゲームで使う」を別の作業にしたのに、後者を進める仕組みも、残りを数える検査も無かった。

## なぜ見つからなかったか
- 残りを数える検査が無く、ゲームの QA は「はじめて開くと遊び方が出る」を正しい動きとして確かめ続けていた。

## 対策
- [x] 直す: `scripts/sync-template.mjs` の migrateFirstPlay が、ひな形からできた形のゲーム（183本）に、はじめての練習の1問と吹き出し（first-play:begin〜end）を足す。QA の前提も migrateFirstQa が替える。練習の入り口が無い・形のちがうゲーム（11本）は、遊び方の窓の代わりにホームのはじめのボタン（チュートリアル・今日の問題）へ吹き出しを1つ出す形（firstTipBlock）を同じ印で足す。
- [x] 防ぐ: `scripts/drift-check.mjs` の `first:howto` が、はじめて開くと遊び方の窓を開くゲームを全部知らせる。
- [x] 見つける: `scripts/game-explore.mjs` が、新しく開いて遊び方の窓（dialog[open]）が出たら不具合として Issue に書く。

## 追記（同じ日、配ったあと）
- 起きたこと: 配った PR のうち、練習の問題の数を決めているゲーム（読み直しで数のちがう回を捨てる。地図記号よみ）と、問題の画面に題（h1）が無いゲーム（お札のひみつ）で、練習が始まらずホームに戻ったり、吹き出しを付ける所が無かったりして、吹き出しが隠れたまま残った。QA は吹き出しが「ある」しか見ていなかったので通った。
- 直す: 1問に減らした回が読み直しで消えたら、元の数のまま練習する。題が無ければ画面の上（header）に付ける。QA の書き換えで残る形（Esc の保存・開いたときの「わかった」）も足した。
- 防ぐ: QA の「吹き出しが出る」は、見えるまで待って確かめる形に替える（firstVisible。前に写したゲームにも次の写しでかかる）。game-explore は、はじめて開いて吹き出しが隠れたままなら不具合にする。
- 2回目の配り直しで止まった8本：GitHub の上でだけ、練習をやめたあと下の「遊び方」が見やすさのボタン（左下）の下に来て押せなかった（詐欺みぬき・切符10。CI でその場の画面を出して確かめた）。はじめての日のホームのボタンを数える検査・Esc の検査（権限チェック・くすりよみ・天気図よみ）も前提ちがいだった。
- 直す：QA は遊び方を openHow() で開く・吹き出しは始まっていれば止める・止めたらページの上へ。案内を閉じたときもホームのいちばん上へ。検査の書き換えを firstLate に足した（前に写したゲームにもかかる）。
