# 詐欺みぬきの QA が、11/18 の今日の問題でだけ古いタブの検査で止まり、main が赤になった

- 種類: 公開・CI
- 場所: sagi-minuki の `qa/run.mjs`（「別のタブで先に答えた問題を、古いタブで二重に入れない」）
- 気づいた人: CI（ci-failure の Issue sagi-minuki #12）
- 影響: sagi-minuki の main の QA が 11/18 0:00（日本時間）から赤。遊ぶ人には影響なし（ゲームは正しく動いていた。検査の不具合）。

## 起きたこと
- 11/17 23:54 に始まった main の QA が、日付が 11/18 に変わったあとの問題で `page.click: Timeout 30000ms exceeded. @157` で落ちた（同じコミットの PR の QA は 11/17 の問題で通っていた）。
- 検査は、古いタブで2問目を読んでから、別のタブで2問目を先に答え、古いタブで「あやしい」→ あやしい所の文 → 決定、と押していた。
- アプリは正しく「別の画面で先に進んでいます」と出して3問目の最初の画面に戻す。11/18 は3問目がふつうの連絡で、あやしい所の文が無く、検査がそこで止まった。3問目が詐欺の日はたまたま通っていた。

## 原因
- 検査が「押す前に読んだ問題」で続きを押していた。古いタブの検査では、押したあとに画面が別の問題に替わるのが正しい動きなので、続きの押し方は日によって合わなくなる。
- QA は「今日」の問題だけで回り、日付を外から変える口（`QA_DATE`・`QA_SHIFT_DAYS`）が無かったので、ほかの日の問題では一度も確かめていなかった。

## なぜ見つからなかったか
- PR の QA は作った日の問題だけで回る。日によって変わる問題で検査を何日分も回す決まりは「この形の問題なら」の検査だけにあり（`incidents/2026-11-17-known-game-bugs-spread.md`）、古いタブ・別のタブの検査には無かった。
- 落ちた日が過ぎると、手元で同じ日の問題を作れず再現できない。ci-failure の Issue にも、どの日の問題で落ちたかが書かれていなかった。

## 対策
- [x] 直す: 古いタブでは1回押すだけにし、「記録は2問のまま・次の問題の最初の画面」を14日分の問題で確かめる。`QA_DATE=YYYY-MM-DD` で日付を止めて回し直せるようにした（sagi-minuki #13）
- [x] 見つける: drift-check の `qa:today-only` が、時計を今日に止めるのに `QA_DATE`・`QA_SHIFT_DAYS` が無い QA を週次まとめに出す（`scripts/game-patterns.mjs` の `todayOnly`。`scripts/check-game-patterns.mjs` で検査。この PR）
- [x] 弱める: ci-failure の Issue に「実行を始めた日（日本時間）」と `QA_DATE=<その日> node qa/run.mjs` を書き添える。翌日でも同じ日の問題で再現できる（`ci-failure-issue.yml`。この PR）
- [x] 防ぐ: routines/game-dev-detail.md の QA の行に「古いタブ・別のタブの検査は、押したあとの画面を読み直してから次を押す。日付で変わる画面の検査は14日分以上回す」を足した（この PR）
