# うそつき六法の条文の PR が、レビューの指摘を読む前にマージされた

- 種類: 手順の抜け
- 場所: usotsuki-roppo（うそつき六法）の PR #5・#6
- 気づいた人: CodeRabbit（マージ後に届いた指摘）
- 影響: 少額訴訟の異議の期間の説明で「判決に代わる調書の送達からも数える」が抜けたまま、数分間公開された。#5 は CodeRabbit のレビューが付く前に自動マージされた

## 起きたこと
- 2026-10-31、#5（本番版）は QA が通った約2分後に `automerge.yml` が自動でマージし、CodeRabbit は「PR が閉じた」でレビューできなかった。
- #6（ページ追加）はラベル「自動マージしない」を付けて CodeRabbit を待ち、1回目の指摘3件は直した。直した版で CodeRabbit のチェックが緑になったのを見てマージしたが、同じ時刻に新しい指摘が1件付いていた。

## 原因
- 自動マージは CodeRabbit のレビューを待たない。条文の中身の PR でも、QA が通れば先にマージされる。
- 手でマージするとき、チェック（check run）の緑だけを見て、今の head へのレビューのスレッドを読み直さなかった。CodeRabbit はチェックを緑にするのと同じころに指摘を書く。

## なぜ見つからなかったか
- `routines/pr.md` は「未解決のレビューが無ければマージ」と書いていたが、確かめる時点と方法が決まっていなかった。

## 対策
- [x] 直す: 少額訴訟の異議の期間を「判決書か調書の送達から2週間」にした（usotsuki-roppo #7）
- [x] 防ぐ: `routines/pr.md` の「5. マージ」に、手でマージする直前に今の head へのレビューのスレッドを読み直す（チェックの緑だけで決めない）を足した
- [x] 防ぐ: usotsuki-roppo の `AGENTS.md` に、ページ（条文）を変える PR はラベル「自動マージしない」を付けて CodeRabbit のレビューを待つ、を足した（usotsuki-roppo #7）
