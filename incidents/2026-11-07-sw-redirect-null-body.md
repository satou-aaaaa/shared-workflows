# sw.js が、リダイレクトと本文の無い返事で例外になっていた

- 種類: 検査の見逃し
- 場所: `template/sw.js`（ひな形 版10）と、それを写したゲーム
- 気づいた人: gurafu-minuki #5・chikei-ate #3・kondate-koma #3 の CodeRabbit（版10を写した PR）
- 影響: 末尾の / の無い URL（例 `…/gurafu-minuki`）を開くと、GitHub Pages のリダイレクトを作り直そうとして例外になり、保存した画面かエラーが返っていた。503 や通信の失敗のあと控えの検索が止まると、60秒の時計が先に止められ、画面が読み込み中のままになりえた。

## 起きたこと
- 版10の sw.js は、ok でない500未満の返事を本文ごと `new Response(buf, { status })` で作り直していた。リダイレクト（status 0）と 204・205 は作り直せず例外になる。
- 500以上と通信の失敗の道では、控えを探す前に `done()` で最後の時計（60秒）を止めていた。

## 原因
- 作り直しの道を、本文のある返事しか考えずに書いた。
- 「最後の時計は、返すまで止めない」という決まりを、成功の道にしか当てていなかった。

## なぜ見つからなかったか
- `template/qa/sw-check.mjs` は 200 の返事と、止まる・遅い返事しか作っていなかった。リダイレクト・204・503・通信の失敗を作る検査が無かった。

## 対策
- [x] 直す: status 0・204・205・304 は作り直さずそのまま返す。500以上と通信の失敗は、返してから時計を止める（`template/sw.js`、#259）
- [x] 防ぐ: `template/qa/sw-check.mjs` に redirect・empty・down503・downErr の4つを足した。版10の sw.js では4つとも落ち、直したもので通るのを確かめた（#259）
- [x] 見つける: ゲームに写すと、どのゲームの QA でも同じ検査が回る（`checkSwStall`。ちがう写しは `scripts/drift-check.mjs` の `sw:template` が出す）
