# Permission guard が、ラベルを付ける数秒前の「PR を作った」実行で毎回落ちていた

- 種類: 公開・CI
- 場所: shared-workflows の Permission guard（`.github/workflows/permission-guard.yml`）
- 気づいた人: satou さん（CI 失敗の一覧 10/21〜11/3）
- 影響: 10/21〜11/1 に6回失敗。うち5回（#64・#72・#86・#87・#105）は、satou承認 のラベルが4〜71秒後に付いて同じ PR が通っていた。残る1回（#98、10/31）は autonomy.md を承認なしで変えたのを正しく止めたもの。

## 起きたこと
- エージェントが権限の表（common.md など）を変える PR を作り、すぐにラベル「satou承認」を付けていた。
- PR を作る API はラベルを一緒に付けられないので、`opened` の実行はラベル無しの中身で走り、落ちた。数秒後の `labeled` の実行は通った。
- #105 は、common-detail.md を足す push（`synchronize`）の10秒後にラベルを付け、同じく1回落ちた。

## 原因
- 関門が「イベントが起きた瞬間の PR のラベル」（イベントの中身）だけを見て、その場で落としていた。作ってからラベルを付けるまでの数十秒の間が考えられていなかった。
- 手順書（pr.md）に、権限の表を変える PR はいつラベルを付けるかが書かれていなかった。

## なぜ見つからなかったか
- 次の `labeled` の実行が緑になり、PR の画面では通って見えたので、赤い実行が残っていることに気づかなかった。

## 対策
- [x] 直す: 関門がラベルをイベントの中身ではなく今の PR から読み、`opened`・`synchronize`・`reopened` では最大3分（10秒ごと）待ってから決めるようにした。待っても付かなければ今までどおり落とす（この PR、`.github/workflows/permission-guard.yml`）。作り物の gh で、2回待って付けば通る・付かなければ落ちる・外せば落ちるを確かめた
- [x] 防ぐ: pr.md の「2. PR を作る」に、権限の表を変える PR は「はい」があるときだけ作り、作ったらすぐラベルを付ける（`gh pr create --label`・issue_write）と書いた（この PR、`routines/pr.md`）
