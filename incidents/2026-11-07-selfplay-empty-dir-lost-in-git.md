# carcassonne-research の selfplay が、直した次の回も「data フォルダが無い」で落ちた

- 種類: 検査の見逃し
- 場所: carcassonne-research の selfplay（自己対戦ループと状態ブランチ selfplay-state）
- 気づいた人: 共通部品 ci-failure-issue（Issue #143）と見回り
- 影響: 11/06 夜・11/07 朝の2回続けて赤。自己対戦が約12時間止まった（チャンピオンと公開ページへの影響はない）。

## 起きたこと
- 11/06 の件（2026-11-06-selfplay-attempt-1000-digits.md）で、片付けが試行1003 のデータまで全部消し、空の `loop/data/` のまま状態ブランチに保存された。
- git は空のフォルダを残さないので、次の回では `state/loop/data/` そのものが無かった。
- #142 で「データが無ければ自己対戦からやり直す」ようにしたが、自己対戦の保存はフォルダを作らないので `FileNotFoundError` で落ちた（11/07 07:16 UTC）。

## 原因
- ループは「フォルダは最初の1回に作れば、あとはずっとある」と決めていた。実際は状態を毎回 git のコミットで受け渡すので、空になったフォルダは次の回には無い。

## なぜ見つからなかったか
- #142 のテストは一時フォルダの中だけで回り、CI と同じ「git を通した受け渡し」を一度も通っていなかった。テストの中ではフォルダが残るので、本番でだけ起きる形を見逃した。
- 直した PR は「次の回で立ち直る」と書いたが、マージ後に main で回して確かめていなかった。

## 対策
- [x] 直す: 状態を読み込むたびに data/・models/・gate/ を作り直し、保存の直前にも親フォルダを作る（carcassonne-research #144）
- [x] 防ぐ: 状態を1単位ごとに本物の git でコミット→clone して取り出しながら、自己対戦→学習→判定→初代と対戦→次の試行まで回すテストを足した。data/ が丸ごと消えた所からも続くかを見る（`test_loop_survives_state_passed_through_git`、carcassonne-research #144）
- [x] 防ぐ: 再発防止の手順（saihatsu-boushi の控え）に、状態を git・キャッシュ・アーティファクトで受け渡すものは、テストでも同じ受け渡しを通す、直したらマージ後に本番の道筋で1回回して確かめる、と足した（この PR）
