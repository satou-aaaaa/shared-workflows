# sandbox の Issue/PR 定期対応が、手順書のある sandbox を読めずに何もせず終わった

- 種類: 手順の抜け
- 場所: ルーティン「Issue/PR定期対応 (kensetsu-kyoka-toolkit)」
- 気づいた人: そのルーティンの回（自分で報告した）
- 影響: 2026-11-01 の回で sandbox の Issue・PR を1件も見なかった

## 起きたこと
2026-10-28、トークン節約のためプロジェクトのリポジトリを3つ（のちに4つ）に絞り、sandbox を外した。
ルーティンのプロンプトは「チェックアウト済みの sandbox の `docs/routines/issue-pr.md` を読む」のままだった。
2026-11-01 の回で sandbox が無く、決まりどおり何もせずに報告して終えた。

## 原因
手順書が、ルーティンを動かすプロジェクトに入っていないリポジトリにあり、プロンプトが「すでにチェックアウトされている」ことを前提にしていた。リポジトリを外したときに、それを当てにするルーティンを見直す手順が無かった。

## なぜ見つからなかったか
リポジトリを絞ったときは、各スレッドが add_repo で足せばよいと決めたが、プロンプトが「チェックアウト済み」と書いたルーティンは自分で足さない。土曜の見直しは catalog.md とルーティンの一覧を突き合わせるだけで、手順書のあるリポジトリがプロジェクトに入っているかは見ていなかった。

## 対策
- [x] 直す: 手順書を shared-workflows の `routines/sandbox-issue-pr.md` に移し、catalog.md・bootstrap/routines.md を直した（この PR）
- [x] 防ぐ: 移した手順書の手順1で、sandbox を add_repo（access push）で自分で足す。プロジェクトのリポジトリの並びに左右されない（`routines/sandbox-issue-pr.md` 手順1）
- [ ] 見つける: ルーティンのプロンプトを新しい文に替える（画面の操作。担当: satou さん、期限: 2026-11-08）
