# 再発防止（satou の決まり、2026-10-19）

問題が起きたら、その件を直すだけで終わらせない。決まりの正は satou-aaaaa/shared-workflows の `routines/common.md`「問題が起きたら（再発防止）」、記録の書き方は `incidents/README.md`。

1. 直す: 起きた問題そのものを直す。
2. 原因: なぜ起きたかを調べる。人や AI のせいにせず、仕組みのどこに穴があったかを書く。
3. 見逃し: 自動検査・レビュー・見回り・手順で、なぜ見つからなかったかを調べる。
4. 仕組み: 同じ種類の問題が二度と起きないように仕組みを直す。例: 自動検査やテストの追加、CI の判定の追加、手順書・決めたことの文書の更新、ツールの直し。「注意する」「気をつける」は仕組みではない。
5. 確かめる: 直す前の版で新しい検査が不合格、直した版で合格になることを確かめる。
6. 記録: shared-workflows の `incidents/YYYY-MM-DD-<名前>.md` に1件1ファイルで書き、`incidents/README.md` の一覧に1行足す（PR で。Lint が形を見る）。個人情報が絡む件は非公開の ops-backup の `incidents/` に同じ形で書く。その場で入れられない対策は `- [ ]` に担当と期限を書く。
7. 繰り返し: 記録の一覧に同じ「種類」が30日以内にもう1件あれば、一つ一つの対策が効いていない。共通の穴を探し、もっと根本の仕組みを入れる。
8. 報告: 「直したこと」と「再発防止に足した仕組み」を分けて、日本語で書く。記録へのリンクを添える。

その場で仕組みまで入れられないときは、何が足りないかと次に何をするかを報告と記録に書く。
