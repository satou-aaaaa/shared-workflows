# ゲームのおもしろさの見直し（週1・月曜 15:47 JST）
<!-- style: v1 -->

先に `common.md` と `autonomy.md` を読むこと。（satou さんの依頼 2026-11-21「おもしろさの見直し（週1）：AIが実際に遊んで、簡単すぎ・単調な所を直す」）

## 目的

公開中のゲームを1回2本ずつ AI が実際に遊び、「簡単すぎる」「単調（また同じ）」な所を1本につき1つ直す。水曜の「1本磨く」（[game-dev.md](game-dev.md) の B）が最後に直した日の古い順に全体を磨くのに対し、ここは数と遊んだ記録で「簡単すぎ・単調」だけを見る。

## 考え方（調べた要点と出典）

- うでに対して手ごたえが低すぎると退屈、高すぎると不安になる。その間（フロー）に入れるよう、慣れた人には次の段階を、困った人には助けを用意する。[Jenova Chen「Flow in Games」（Communications of the ACM, 2007）](https://cacm.acm.org/magazines/2007/4/5692-flow-in-games-and-everything-else/fulltext)
- 学びには「望ましい難しさ」がある。間をあけて思い出す・種類を混ぜて解くと身につく。すぐ同じ問題が戻る・1種類ばかり・見ただけで当たるのは、楽だが身につかない。[Bjork & Bjork「Making things hard on yourself, but in a good way」（2011）](https://bjorklab.psych.ucla.edu/wp-content/uploads/sites/13/2016/04/EBjork_RBjork_2011.pdf)
- AI に遊ばせて難しさを測るのは、人のテストの代わりにはならないが、難しさの相対的な順番や偏りを見つけるのに使える（人がつまずく所と AI がつまずく所は似る）。[Xiao ほか「LLMs May Not Be Human-Level Players, But They Can Be Testers」（arXiv 2410.02829, 2024）](https://arxiv.org/abs/2410.02829)
- だから、数（`scripts/game-fun.mjs`）で偏りを見つけ、実際に遊んで確かめてから直す。数だけで直さない。

### 目安の理由（`scripts/game-fun.mjs` の LIMITS）

| 数 | 目安 | 理由 |
| --- | --- | --- |
| 今日の問題のうち、前の7日と同じ問題 | 20% 以下 | 毎日遊ぶ人が「昨日もやった」と感じない（間をあけた想起） |
| 28日の今日の問題に出る種類 | 70% 以上 | 種類を混ぜる（交互の練習） |
| 1つの種類から30回作ったちがう問題 | 5 通り以上 | 練習・とことんで同じ問題が続かない |
| 作れるちがう問題 | 60 通り以上 | 毎日5問なら12日以上は新しい問題が出る |
| 正解がいつも同じ位置・正解だけいちばん長い | 50%・40% 以下 | 中身を読まずに当たる手がかりを作らない |
| 上級の問題の段階（lv の平均） | 今日の問題より高い | 慣れた人の次の目標になる |

## 使う道具

- `node scripts/game-fun.mjs <ゲームのフォルダ>`：簡単すぎ・単調の数（△ は遊んで判断。make() が無いゲームは「遊んで見る」と出る）
- `node scripts/game-play.mjs <フォルダ> <go-d|go-h|go-p> <long|first|rand> [回数]`：スマホ幅（390×844）で通しで遊び、初めの1回で当たった数を出す（ひな形の画面のゲーム）
- 台帳 [`fun-review.md`](../fun-review.md)：どのゲームをいつ見たか
- 報告の返信：Claude 以外は [tool-map.md](tool-map.md) の置き換え先

## 手順

1. 節約モード（common.md）なら何もせず、update_status に1行書いて終える。
2. shared-workflows を `git pull origin main` で新しくする。
3. `node scripts/repos.mjs game` でゲームの一覧を出す。
4. 台帳 `fun-review.md` に無いゲームを名前の順に、無ければ「見た日」がいちばん古いゲームから、2本選ぶ。
5. 選んだゲームがこの会話で読めない（`gh api` が「access to this repository is not enabled」）なら、`add_repo`（access: push）で足す。足せなければ飛ばし、次のゲームを選ぶ。
6. 選んだゲームに開いている PR があれば飛ばし、次のゲームを選ぶ（`gh api repos/satou-aaaaa/<ゲーム>/pulls?state=open`）。
7. 1本ずつ `git clone --depth 1 https://github.com/satou-aaaaa/<ゲーム>` する。
8. `node scripts/game-fun.mjs ../<ゲーム>` を回し、△ を書き出す。
9. `bash scripts/setup.sh` を回す（そのゲームのフォルダで）。
10. 遊ぶ。ブラウザはクラウドの会話では `CHROMIUM_PATH=/opt/pw-browsers/chromium` を前につける。
    - 選ぶ問題のゲーム：`node ../shared-workflows/scripts/game-play.mjs . go-d rand 3`・`long 3`・`first 3` を回し、初めの1回で当たった数（first）を比べる。long か first が rand より3割以上多ければ「見ただけで当たる」。上級（`go-h`）と練習（`go-p`）も1回ずつ。
    - パズルなど選び肢の無いゲーム：その日の問題を、いちばん得になる手を毎回選ぶだけのやり方（欲ばり）で解くスクリプトを書き、大きさごとに「欲ばりで最少の手数に届く割合」を出す。いちばん大きい問題・上級で5割を超えたら簡単すぎ。
    - どちらも、かかった秒数・まちがえた数・「読まずに当たった問題」の数を書く。
11. 下の「直すもの」の表で、いちばん効くものを1つ決める。
12. 直す。`qa/run.mjs` に、直したことの検査を1つ足す。
13. `node qa/run.mjs` を通す（同時に回すのは2本まで）。
14. PR を出す（[pr.md](pr.md)）。題は「おもしろさ：<何を直したか>」。本文に「遊んだ記録（秒数・まちがい・読まずに当たった数）」「game-fun の △」「なぜそれを直したか」「調べた要点と出典」を書く。
15. 台帳 `fun-review.md` に、見た日・遊んだ記録の短いまとめ・PR を書き（名前の順の位置。もうある行は書きかえる）、shared-workflows に PR を出す。
16. 遊んで見つけた偏りが `scripts/game-fun.mjs` で見つけられない形なら、測り方を足し、`--self-test` の見本にも足す（同じ PR に入れる）。
17. 報告の届け先のスレッドに、2本の結果を3行以内で返す。

## 直すもの

| もし | すること |
| --- | --- |
| 今日の問題が前の7日と同じ問題ばかり（△ 前の7日） | 今日の問題の選び方（`dailyTags`）で、7日以内に出た種を避ける |
| 種類が偏る（△ 出る種類） | 今日の問題の選び方で、出ていない種類を先に選ぶ |
| 1つの種類の問題が少ない（△ 通りに満たない） | その種類の問題を、出典を読んで足す（`game-dev.md` の出典の決まり） |
| 選び肢の位置・長さで当たる | 選び肢を並べ替える・長さをそろえる（[game-ja.md](game-ja.md) の「正解だけ長い」） |
| 上級が今日の問題と同じ難しさ | 上級を難しい段階の種類から選ぶ・選び肢を増やす |
| 今日の問題が 60 秒未満で、まちがい0で終わる | 難しい段階の問題を1問足すか、最後の1問を一段難しくする |
| 解き終わった後に次の目標が無い | 「とことん」の記録・やりこみの段階など、ひな形の共通の形（`template/depth.js`）の足りない部品を足す |
| 遊び方を変える案（ルール・世界観・お金・外への通信） | 直さない。satou さんにカードで1件だけ聞く（質問の先頭に「satouさんにお願い：」） |
| どの △ も無く、遊んでも困りごとが無い | 直さない。台帳に「直す所なし」と書く |
| どれにも当たらない | 止めて、そのゲームの Issue（ラベル needs-decision）に状況を書く |

## 完了条件

- 選んだ2本を実際に遊び、記録が PR か台帳にある
- 2本それぞれ、PR が出ているか、台帳に「直す所なし」と書いてある
- 台帳の PR が shared-workflows に出ている

## やってはいけないこと

- 遊ばずに、数（game-fun の △）だけで直す
- `KINDS`・言い回しの配列の並べ替え・削除（過去の日の問題が変わる）
- 答えの中身を、出典を読まずに変える
- 1本に2つ以上の直しを入れる（何が効いたか分からなくなる）
- 3本以上を1回で見る（トークン節約。1回2本まで）
