# 古くなる情報の見直し（毎週火曜 10:43 JST・新作を作るとき）
<!-- style: v1 -->

## 目的
学習ゲームの中の、時間がたつと古くなる情報（法律・税の金額・料金・制度・一覧）を、出典と照らして正しいままにする。
台帳は [../freshness.md](../freshness.md)。見直しが要るゲームは、毎週火曜 05:43 JST に Freshness（`freshness.yml`）が Issue「古くなる情報の見直し」に出す。

## 使う道具
- git・Node.js 22・GitHub（Issue・PR）
- 出典を読む道具（web-fetch。クラウドから開けないサイトは [known-limits.md](known-limits.md) の回り道。e-Gov の条文は `https://laws.e-gov.go.jp/api/2/law_data/<法令ID>` で読める）
- 知らせ・確認：Claude はプロジェクトチャットのカード。ほかの AI・人は [tool-map.md](tool-map.md) の置き換え先

## 手順
1. 節約モード（[common.md](common.md)）なら何もせず、1行だけ報告して終える。
2. このリポジトリで Issue「古くなる情報の見直し」（ラベル「情報の見直し」）が開いているかを見る。無ければ、1行だけ報告して終える。
3. Issue に出た行の上から、1回に**3本まで**選ぶ（開いた PR があるゲームは飛ばす）。
4. 選んだゲームを `git clone --depth 1 https://github.com/satou-aaaaa/<リポジトリ>` する。
5. そのゲームの README の「出典」と、Issue に出た改正（法令名・公布日・施行日）を読む。
6. 出典（一次資料）を1つずつ開き、ゲームの中身（`data.js`・`gen.js`・`index.html`・README）と照らす。出典の文はメモに引用で残す（[../incidents/2026-11-18-game-copy-leftovers-and-source-mixup.md](../incidents/2026-11-18-game-copy-leftovers-and-source-mixup.md)）。
7. 下の表で、することを決める。

   | もし | すること |
   | --- | --- |
   | ゲームの中身が今の出典と同じ | 手順 9 へ（ゲームは直さない） |
   | 中身が古い（数字・条文・一覧がちがう） | そのゲームの AGENTS.md と [pr.md](pr.md) に従って直し、`qa/run.mjs` に、新しい値を確かめる検査を1つ足して PR → CI 緑でマージ |
   | まだ施行されていない改正があり、施行の日からゲームが古くなる | 今は直さない。手順 9 で「次に見る日」を施行の日の7日後にし、「古くなる情報」の列に「〇年〇月〇日から〇〇が変わる」と書き足す |
   | 出典が開けない・読み方が分からない | 手順 9 をせず、Issue に「<リポジトリ>：<分からない点>」とコメントして次のゲームへ |
   | どれにも当たらない | 止めて、Issue にコメントで状況を書く |

8. ゲームの答えが変わる直し（法律の結論・金額）は、PR 本文に出典の URL と引用した文を書く。
9. このリポジトリの [../freshness.md](../freshness.md) の行を直す：「確認した日」を今日に、「次に見る日」を「見直しの時期」の次の日（無ければ1年後）にする。
10. `node scripts/freshness.mjs --lint` を回して通す。
11. このリポジトリに PR を出す（題「古くなる情報の見直し：<リポジトリ>…」）。Lint が緑ならマージする。
12. 全部の行が済んだら、次の火曜の Freshness が Issue を自動で閉じる（手で閉じない）。
13. 報告は「見直した本数・直したゲーム・次に見る日」の3行だけ。satou さんの手が要るときだけカードで聞く。

### 新作を作るとき（[game-dev.md](game-dev.md) 手順8）
1. 一覧に足す PR で、[../freshness.md](../freshness.md) にも名前の ABC 順の位置に1行足す。
2. 古くならない題材（理科・ことば・パズル・作り話）は「古くなる情報」を `なし（理由）`、「次に見る日」を `—` にする。
3. 法律・税・料金・制度・一覧を使うなら、「法令」に使った法令の ID（`laws.e-gov.go.jp/law/<法令ID>`）を全部書き、「確認した日」を作った日にする。

## 完了条件
- 選んだゲームが、今の出典と同じ中身になっている（直した PR はマージ済み）。
- [../freshness.md](../freshness.md) の選んだ行の「確認した日」が今日になり、`node scripts/freshness.mjs --lint` が通る。
- 台帳の PR がマージされている。

## やってはいけないこと
- 出典を読まずに「確認した日」だけを進めない（見張りが黙るだけで、古いまま残る）。
- 一次資料（法令・官公庁・公式の発表）でない記事だけを根拠に直さない。
- Issue を手で閉じない（Freshness が次の回に閉じる）。
- 1回に4本以上を直さない（レビューの目が足りなくなる）。
- 個人情報や satou さんの事情を Issue・PR に書かない（公開リポジトリ）。
