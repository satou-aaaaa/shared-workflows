# ルーティンとスキルの定期見直し（週1・土曜朝）

先に `common.md` を読むこと。提案のみで、変更は satou さんの OK が出てから行う。チームメモリ routine-review と efficiency-rules を先に読む。
（satou さんの依頼 2026-10-14「ルーティン等、定期的に見直すようにしてください」「skills 等の提案も定期的に行うようにしてください。また、見直しも同様に」）

## A. ルーティン

1. list_triggers（enabled=true、全ページ）で有効なルーティンを確認する。前回の提案（このスレッドの直近の reply とチームメモリ routine-review）と比べ、反映済みかどうかも確かめる。
2. 次の観点で見る:
   - a. 利用上限による FAILED が続いているもの、頻度が高すぎるもの、目的が重なっているもの（同じリポジトリ・同じ作業を2本が担当、同じPRを重複して作る等）、実行時刻が集中しているもの、使っていない・役目を終えたもの、重い作業に高いモデルを使っているもの。
   - b. 提案係の採用率: 提案を出す係（全リポジトリ巡回・新規Issue提案・LAST TELL の毎日の改善提案・運用エージェントのスカウトなど）ごとに、その週の提案数と採用数（マージ・着手されたもの）を数え、2週続けて採用0の係は停止か頻度を下げる案を出す。
   - c. Claude が要らない作業: 決まった手順だけの定期作業が Claude のルーティンで回っていたら、CI へ移す案を出す（使える部品は shared-workflows の `.github/workflows/`）。
   - d. 長寿命スレッド: 毎月最初の土曜の回だけ、何度も起こされる持続セッション（監督・巡回・小江戸など）を get_session で点検し、重くなっていれば要点をメモリに書いて新しいスレッドに付け替える案を出す。
   - e. 節約モードとの整合: 直近の利用上限による失敗が、守る順番どおりに防げているかを見る。
   - f. モデル: スレッドに届く型のルーティンのモデルが、決めた軽いモデルに切り替わっているか（2026-10-14 satou さん承認：ソースの控え・連載の予約切れチェック・週次の研究まとめは Haiku、他は Sonnet）。get_session で確かめ、未反映のものだけ一度「satouさんにお願い：」で思い出してもらう（同じものを2回は言わない）。
   - g. 共通化: プロンプトが長いまま（手順が `routines/` に移っていない）ルーティンや、`common.md` と同じきまりをプロンプトに書き直しているものがあれば、`routines/` に移す案を出す。

## B. スキル

3. 新しいスキルの提案: この1週間のこのプロジェクトのスレッド（list_thread_sessions・fetch_thread、直近の分だけ）とチームメモリから、同じ手順を2回以上手でやっているものを探す。既存スキルで足りるものは除く。
4. 既存スキルの見直し: satou さんのスキル（anthropic-skills:* と、各リポジトリの .claude/skills/）の SKILL.md を読み、古くなった内容（存在しないファイル・ツール・手順、今のルールや方針との食い違い）を探す。1回に見るのは最大5本で、前回見たものは後回しにする（見た日付は routine-review に記録）。
5. 新規・修正とも、提案するものだけ propose_skills でカードを出す（1回最大3件。修正は今の SKILL.md 全文を読んでから、更新後の全文で出す）。スキルのファイルを直接書き換えない。

## C. 次にできること

（satou さんが「他にできることは？提案して」を何度も頼んでいたのを自動化。2026-10-16 承認）
6. A・B とは別に、satou さんの手間を減らす・アプリをよくする「次にできること」を最大3件出す。材料はこの1週間のスレッド・状況ページ・satou さんの TODO（/mnt/project-files/notes/todo.md）。
   既に動いている仕組み（このフォルダの手順・shared-workflows の部品）と、過去に出して答えが無い・見送られた案は除く。費用が増える案は出さない。
7. 1件ずつ ask_decision のカード（質問の先頭に「satouさんにお願い：」）で採るか聞く。採用されたものはこのプロジェクトのコーディネーターにスレッド開始を頼み、メモリ routine-review に「出した案と答え」を1行ずつ残す。

## 共通

8. 節約モードのときは B と C を飛ばして A だけにする。
9. 新しい提案があるときだけ、このスレッドに reply で番号つき1行ずつ（何を・どう変える・理由）にまとめ、ルーティンの分は ask_decision で反映するか聞く（スキルの分はカードで聞くので reply に1行で触れるだけ）。何も無ければ update_status だけ更新して no_reply_needed。
10. satou さんが OK したルーティンの変更だけを update_trigger / delete_trigger で行い（他スレッドに紐づくルーティンの prompt はそのセッションに send_message で依頼）、結果を1行で報告する。メモリ routine-review を更新する。
