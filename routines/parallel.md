# 並列で進めるとき（サブエージェント・worktree・別スレッド）

いくつかの作業を同時に進めるときの決め方。satou さん（2026-10-21「実装は必要なら並列で」）。
`common.md`「読み方」のサブエージェントの数とモデルの決まりは、調べものの節約のためのもの。実装を分けるときはこのファイルで決める。

## 分けてよいか（先に決める）

| もし | すること |
| --- | --- |
| 作業どうしが同じファイルを触る | 分けない。順番に1つずつ |
| 片方の結果がないと、もう片方を始められない | 分けない。順番に |
| 触るファイルが重ならず、それぞれ「終わった」と確かめる検査がある | 分けてよい |
| 何をするかがまだぼんやりしている | 分けない。先に1つで計画を作る（ぼんやりした作業を2つ並べても速くならない） |
| 広く読むだけ（調べもの・一覧づくり） | サブエージェントに要約だけ返させる（`common.md`「エージェントの使い方」） |

## 分け方

| 何を分けるか | 使うもの | 決まり |
| --- | --- | --- |
| 同じリポジトリの別々の変更 | `isolation: "worktree"` のサブエージェント（1つにつき1つの worktree と1つのブランチ） | ブランチ名に作業の名前を入れる。終わったら worktree は消える（変更が無ければ自動） |
| 別々のリポジトリの変更 | サブエージェント（worktree は要らない） | 1つのサブエージェントは1つのリポジトリだけ |
| 何日も続く・satou さんとのやりとりがある | 別のスレッド（コーディネーターに頼む） | `common.md`「1スレッド1作業」 |
| 同じ問いに複数の案を作って比べる | worktree のサブエージェントを案の数だけ | 比べる観点を先に書いてから渡す |

- 同時に動かすのは **最大3つ**。それより多いと、確かめる側（自分）の見直しが追いつかない。
- サブエージェントに渡す文には、`common.md`「頼むときは3点」（対象・やらないこと・終わったと言える確かめ方）を必ず書く。共有フォルダを使うときは、その注意（末尾の `/`、書いたら読み直す）も書く。
- 実装を任せるときは model を指定しない（自分と同じモデル）。調べものだけなら haiku でよい。

## 合わせ方

1. 返ってきた変更を1つずつ自分で読む（サブエージェントの「できた」は確かめた証拠ではない）。
2. PR は分けた単位で1本ずつ出す。まとめると、どれが壊したか分からなくなる。
3. 同じファイルに触れていたと分かったら、後から来たほうを main に合わせて直してから出す。
4. 各 PR の検査が緑になってからマージする。マージの順は、ほかが当てにするものを先に。

## やってはいけないこと

- 同じブランチ・同じ worktree を2つのエージェントで使う（変更が消える）。
- satou さんの答え待ちのものを、答えの前提で並べて進める（答えが違うとやり直しになる）。
- 並列で作った変更を、確かめずにまとめてマージする。

## 調べた要点と出典

- 同時に動かすセッションは、git の worktree でそれぞれ別のブランチに分け、編集がぶつからないようにする。[Claude Code Docs: Common workflows（Run parallel sessions with worktrees）](https://code.claude.com/docs/en/common-workflows)
- worktree は1作業ごとに作って終わったら消す。長く残すと依存や設定がずれる。ぼんやりした作業を並べても速くならない。各ブランチは別々にレビューする。[MindStudio: Parallel agentic development with git worktrees](https://www.mindstudio.ai/blog/parallel-agentic-development-git-worktrees/)・[LowCode Agency: Claude Code git worktrees](https://www.lowcode.agency/blog/claude-code-git-worktrees)
- 調べものはサブエージェントに任せ、要約だけ受け取って自分の文脈をきれいに保つ。[Claude Code Docs: Delegate research to subagents](https://code.claude.com/docs/en/common-workflows)
